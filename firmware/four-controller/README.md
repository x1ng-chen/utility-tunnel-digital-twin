# 四主控业务固件与S3网关 v2

**完整业务交付版：** [五板构建、软件测试、中文双屏与网关本地配置说明](RELEASE.md)。`tools/build_release.py`统一生成四块STM32镜像和一套S3发布镜像，校验版本/板号、分段烧录布局和SHA256；S3无需把网络凭据编译进固件。软件发布包仍需实体烧录与联调验收。

2026-10-27。四个STM32F103RCT6现场节点＋一个ESP32-S3轮询网关，另一个小智S3保持语音终端用途。旧双节点源文件、V16/V17模型原件和 [10月26日原始台架记录](PROGRESS-20261026.md)保留；这些记录不能证明本版已完成四板实物验收。

本页说明当前源码和接口。构建、软件测试结果与烧录、波形、电平、实测反馈分别记录；本轮不自动烧录或操作真实执行器。

## 布局、身份与引脚

| 节点 | 位置 | 检测站 | 物理传感器数 | 其他职责 |
| --- | --- | --- | ---: | --- |
| CTRL-01 | 左下 | P3＋P5 | 11 | 状态屏 |
| CTRL-02 | 右下 | P4 | 7 | 主屏、摇杆、FAN-02、继电器2、INA226-FAN2 |
| CTRL-03 | 右上 | P2 | 6 | 蜂鸣器、18颗灯带 |
| CTRL-04 | 左上 | P1 | 7 | FAN-01、继电器1、INA226-FAN1 |

共31个物理传感器：MQ-2/MQ-4/CO（MQ-7类）各5、火焰5、温湿度4、液位4、氧气3。SHT两个指标只计一个物理模块；双INA另计执行器反馈。本版完整上行可有54条指标，不能把54当成传感器数量。

逐线表与保留脚例外见 [接线源码对照V0.4](../../docs/hardware/four-controller-wiring-20261026/README.md)。关键修订：

- 两屏统一SPI3：PB3/PB5，RES PB6、DC PB7、CS PB8、BLK PB9；禁JTAG并保留SWD。
- CTRL-02风机PWM为PB1/TIM3_CH4；CTRL-04为PB8/TIM4_CH3。两台TACH均在各自PA7，继电器各自PA1。
- CTRL-01的MQ2-03/05为PC4/PC5；MQ4-03/CO-03/MQ4-05/CO-05依次PA4/PA5/PA6/PA7；LEVEL-03为PB1，O2-02为PA0。
- **O2-02/PA0只是源码一致的未验证例外**：库存板资料曾将PA0列为WKUP按键，板上按键与输入负载须核对，不能凭编译通过认定可用。
- 各板USART2为PA2/PA3、19200 8E1；USART1为PA9/PA10、115200 8N1。软件I²C：4号PB6/PB7，其余PB10/PB11。

总线顺序：GW-01→4→3→2→1，不闭环。仅实际两个端点开启120Ω，其余关闭；JSM485的TXD/RXD按已选模块丝印接，不能套用其他模块命名。S3的TX/RX候选为GPIO17/18。

| 编号 | 标签 | 编号 | 标签 |
| ---: | --- | ---: | --- |
| 1～4 | MQ2-01 / MQ4-01 / CO-01 / FLAME-01 | 17～20 | MQ2-05 / MQ4-05 / CO-05 / FLAME-05 |
| 5～8 | MQ2-02 / MQ4-02 / CO-02 / FLAME-02 | 21～24 | SHT-01～04 |

网关使用版本化清单将编号映射为平台原资产编码，例如MQ2-01→SMOKE-01；不自动重命名历史资产和三维绑定。清单与Agent目录需一致。

## 采集、控制与反馈

- STM32循环中穿插总线服务，SHT转换等待采用状态机，ADC每次有界采样；屏幕每次绘制一行。软件I²C半周期改为微秒级，实际波形和最坏响应时间待台架测量。
- 数字输入由1 ms SysTick观察、连续三次有效消抖；对已观察事件保持10秒，并标记锁存。低于观察窗口的脉冲不能保证捕获，延长保持时间不能恢复未观察事件。
- 手动命令有有限租期，周期采集不再强制覆盖手动目标。每种输出独立计时，本地已定义的烟雾/火焰保护优先；租期到期回到自动目标，报警解除后仅恢复尚未到期的手动目标。
- 风机TACH、INA电压/电流/功率周期读取并携带质量和年龄。继电器命令关闭时不抹掉实际惯性转速或实测电流。
- AO-02只上报raw/mV；MQ原始ADC不是ppm。默认PPR、INA分流电阻/电流LSB尚未校验，相关换算标为suspect，不能声称完成标定。
- LED SPI编码与当前8 MHz时钟配套，传输故障有超时返回；具体灯带版本、驱动电平、复位时序及负载仍需实测。
- CTRL-02摇杆：X选节点、Y选传感器，按键进入动作选择，再按进入确认，确认页按键提交、移动取消；通信与远端视图超时显示未知/过期。CTRL-01没有直接风机或集中蜂鸣器，网关失效后不能跨区联动。

## Modbus RTU v2

地址1～4与物理主控编号一致；19200、8E1。业务签名是0x5554、版本是0x0200，不能与签名0x4853的rs485-bench诊断固件混用。

| 功能码 | 含义 | 地址范围 |
| --- | --- | --- |
| 03 | 读取保持寄存器中的最近命令镜像 | 0～7，共8个 |
| 04 | 读取输入遥测和相关执行结果 | 0～95，共96个 |
| 10（十六进制，即16） | 写多个保持寄存器；提交原子命令或网关视图/回执 | 下述规定窗口 |
| 06 | 不再支持旧三次单寄存器触发命令 | 返回异常，不驱动输出 |

CRC正确的写入应答只证明该事务获得响应。网关必须随后读04的80～85，核对session与nonce再解释结果，不能把写回显当成执行成功。

### 输入寄存器（04）

32位数按高16位在前；标记为有符号的量按二进制补码解释。

| 地址 | 内容 |
| ---: | --- |
| 0、1、2、3 | 签名0x5554、板号、版本0x0200、有效物理传感器数 |
| 4～5、6 | 节点uptime秒（非UTC）、16位采样序列 |
| 7 | 输出设定状态：低8位PWM百分比，bit8继电器设定 |
| 8＋4i | 传感器ID；空槽0xFFFF |
| 9＋4i | 主值：DO 0/1、ADC原值，或有符号SHT温度0.01°C |
| 10＋4i | 辅助值：SHT湿度0.01%RH、O2毫伏，其他0 |
| 11＋4i | 状态：0正常采集、1缺失、2存疑、3已观察事件锁存 |
| 52 | 本区烟雾/火焰保护标志 |
| 53～54、55 | RPM及其质量码 |
| 56～57 | INA总线电压，mV |
| 58～59 | INA电流，有符号µA |
| 60～61 | INA功率，µW |
| 62 | 低8位INA质量；bit8为显式校验的电流标定配置标志 |
| 63 | 与7相同的输出设定状态 |
| 64 | 当前手动租期有效掩码：bit0风机、bit1继电器、bit2蜂鸣器、bit3灯带 |
| 65 | 锁存传感器槽位掩码 |
| 66、67 | CRC错误与RX溢出计数低16位 |
| 68～78 | 每槽观测年龄，10 ms；0xFFFF表示缺失 |
| 79 | RPM年龄，10 ms |
| 80～81、82～83、84 | 最近命令session、nonce、相关执行结果 |
| 85、86 | 本地保护状态、INA年龄（10 ms） |
| 87～88、89、90、91、92 | 摇杆请求nonce、目标板、动作码、参数、剩余租期ms |
| 93、94、95 | 主屏选中节点、摇杆请求待处理标志；95的bit0为输出驱动故障、bit1为本次启动已完成网关握手 |

i=0～10，按本板数组顺序。RPM/INA质量码0=可用、1=缺失、2=存疑；质量码不等同设备整机验收。输出状态是软件施加的控制设定，不是触点、供电或转动的实物证明。

### 原子命令（10，起始0、数量8）

| 寄存器 | 内容 |
| ---: | --- |
| 0 | 动作：1风机PWM、2继电器、3蜂鸣器、4灯带、5恢复自动 |
| 1 | 参数：PWM 0～100；继电器/蜂鸣器0或1；灯带0关/1红/2黄/3绿/4蓝；自动模式参数0 |
| 2 | 相对租期ms，100～60000；平台当前手动默认10000 |
| 3～4 | 网关session，非零32位 |
| 5～6 | 命令nonce，非零32位 |
| 7 | 标志保留，必须0 |

能力按所属板检查：2/4号风机和继电器，3号蜂鸣器和灯带，1号没有可写执行器。重复session/nonce不重新延长租期，参数冲突或旧序号被拒绝。10应答之后读取80～85关联结果：

| 结果 | 含义 |
| ---: | --- |
| 1 | 输出已应用，实际运行仍需反馈 |
| 2 | 该板不支持动作 |
| 3 | 参数无效 |
| 4 | 已过期/旧命令 |
| 5 | 本地保护阻止手动动作 |
| 6 | 冲突重放 |
| 7 | 执行结果未知 |

网关在写超时、返回值不匹配或结果无法关联时上报unknown，不自动重试物理写入。此协议依赖单主控调度，不是总线身份认证协议。

### 主屏数据与本地回执窗口

仅CTRL-02接受10起始256、数量80的网关视图；前80项来自选中节点输入表，必须核对签名/版本/板号。10起始512、数量3写入摇杆nonce高/低16位与结果码。此数据由网关转送，不把CTRL-02变成第二个总线主站；视图过期不表示设备数值为零。

所有节点接受10起始516、数量2的非零32位启动会话。每次复位会清除95的bit1；网关先完成握手，再等待下一次新快照后才发布数据和允许命令。因此同一秒内复位也能识别，不靠uptime下降猜测重启。S3重启会用新会话重新绑定，取消CTRL-02旧的未完成菜单请求并显示未知。菜单结果回执丢失时只补发缓存结果，不再执行动作；真实复位与丢包组合仍需台架验证。

## MQTT与平台契约

网关发布ut/v1/CTRL-01～04/telemetry；JSON保持ut.telemetry.v1/readings契约，并增加frameId、source、controllerId、layoutVersion、rawOnly、clockSource、sampleAgeMs。温度按有符号百分之一度换算，氧气不推导浓度。节点无有效响应时不发布新的正常心跳。已消抖且实际观察到的短数字事件，保持`eventLatched=true`和原观测时间；新鲜且已校时的有效事件可建告警，Django持久保存`observationKind=latched_event`，Agent会明确它不表示输入此刻仍持续触发。缺失、过期、未来或坏质量记录不能恢复在线，也不能错误解除当前告警。

上行包含传感器与独立执行器指标：rotational.speed、supply.voltage、motor.current、power、pwm.duty、relay.commanded。完整四板数据为54条指标，仍是31个物理传感器。

每个命令主题为ut/v1/CTRL-0N/cmd。v2请求仅含7个字段：

| 字段 | 约束 |
| --- | --- |
| schema | ut.command.v2 |
| cmdId | 1～80个受限字符，端到端关联和去重 |
| controllerId | CTRL-01～04，必须与主题一致且动作属于该节点 |
| command | fan / relay / buzzer / led / auto |
| value | 整数，按动作范围检查 |
| issuedAtMs | 服务端实时UTC epoch毫秒 |
| ttlMs | 100～60000，当前平台10000 |

网关使用严格JSON形状/类型/范围检查。缺字段、重复字段、不完整JSON、浮点/字符串冒充整数、错误目标、过期及未来越界请求不驱动输出。尚未校时不接受MQTT硬件命令；数据可标为suspect和receiver-estimated，节点uptime不冒充UTC。

回执主题ut/v1/CTRL-0N/cmd_ack；schema为ut.command-ack.v2，带cmdId、controllerId、status（accepted/rejected/unknown）、reason和physicalStateVerified=false。accepted表示控制器报告输出已应用，不能显示为“风机已转动”。

网关用Preferences命名空间ut-cmd-v2保存64条命令记录。发UART前先保存UNKNOWN；重启后同cmdId不重新下发，原deadline不续期，存储异常时禁止下发。软件测试可检查编码和去重逻辑，不能替代真实NVS掉电/损坏试验。摇杆请求属于幂等设定与剩余租期，不宣称覆盖所有设备重启组合的恰好一次执行。

诊断串口采用同一`ut.telemetry.v1`格式，`verify_sensors.py --port ... --board ...`兼容新`readings`和旧台架`slots`；脚本只在用户指定端口时打开串口。S3诊断发送使用8KB TX缓冲与空间检查，慢速读端可能丢弃诊断行，不能阻塞485调度或据此声称MQTT丢失。

### 服务端切换配置

默认继续legacy模式，以免对现有硬件静默改协议。四节点业务固件和身份验收后，显式配置：

- Django：先备份拟升级数据库，再运行`python manage.py migrate`应用0026迁移；然后配置CONTROLLER_COMMAND_PROTOCOL=four-controller-v2。本轮只迁移测试库，未改现有业务库。
- 网关服务：LOCAL_DEVICE_IDS=CTRL-01,CTRL-02,CTRL-03,CTRL-04。
- S3：复制gateway/include/secrets.example.h为本地忽略的secrets.h，配置实际Wi-Fi和同一个MQTT broker。
- 三端的broker地址、端口与凭据必须一致；本地compose把容器1883映射为主机1884，S3要填主机局域网地址和1884，不能填127.0.0.1。
- 当前仓库local-mqtt是允许匿名的隔离台架配置，不能当作公网控制入口。S3当前是局域网MQTT链路，公网评委入口与生产安全部署另验收。

网页从只读能力API读取当前协议；四节点模式分别确认FAN-01/CTRL-04和FAN-02/CTRL-02的继电器与PWM。确认凭据与操作者、目标、动作和参数绑定；取消不写入，超时不自动重发。Agent测试环境继续禁硬件控制。

## 构建与软件验证

从仓库根目录构建各板：

~~~powershell
cmake -S firmware/four-controller -B build/four-1 -G Ninja -DBOARD_ID=1
cmake --build build/four-1
# BOARD_ID和输出目录分别换成2、3、4
python -m platformio run --project-dir firmware/four-controller/gateway -e s3_four_gateway -e s3_four_gateway_network_check
~~~

STM32输出build/four-N/four_ctrl0N.bin，链接地址0x08000000；构建命令不烧录。S3网络检查环境只使用公开编译占位配置，不上传、不连接真实网络。生产配置放忽略的secrets.h，不能提交密钥或含密钥的固件镜像。

Linux/CI的业务核心及真实JSON解析器测试：

~~~sh
python firmware/four-controller/tests/run_tests.py --native \
  --json-include firmware/four-controller/gateway/.pio/libdeps/s3_four_gateway/ArduinoJson/src
python -m unittest discover -s firmware/four-controller/tests -p 'test_*.py'
python docs/hardware/four-controller-wiring-20261026/generate_plan.py
python docs/hardware/four-controller-wiring-20261026/validate_wiring.py
python -m unittest discover -s docs/hardware/four-controller-wiring-20261026 -p 'test_*.py'
~~~

实际C++编码器的四份输出可通过UT_GATEWAY_FIXTURES指定给网关服务的测试，验证完整31实体/54指标的跨层契约。当前修复结果见[软件验收记录](FIX-VALIDATION-20261027.md)。

Windows可用同一测试入口的--arm-emulated模式执行ARM编译的纯业务核心；它不仿真GPIO、外设时序或整块板。CI同时构建旧固件、四节点业务固件、485诊断固件及S3离线/网络路径，不触发模型付费调用或硬件动作。

## 台架尚需验证

1. 四块实际板的针脚、电平、供电、PA0/WKUP例外和接线连续性；不能把源码表当作实测表。
2. 一主一从及四节点同总线，错误CRC/干扰/拔线/重启后的身份、超时、溢出和恢复；测最坏响应时间。
3. 31路逐项观测、短脉冲最小宽度、锁存/恢复，SHT地址/CRC/负温、模拟输入范围与缺失。
4. 两屏与摇杆确认/取消、远端视图过期、网关离线后的本地行为；软件回执与真实输出分别观察。
5. 两台风机PWM频率/极性、继电器有效电平、PPR、TACH惯性反馈、INA分流/方向/标定及负载并发。
6. 灯带波形/电平、全白负载与故障超时；NVS掉电、broker重连、重复和过期命令均不误触发。
