# 四主控业务固件（第一版）

2026-10-26。把旧双节点 `firmware/stm32f103rct6` 的采集逻辑，按 V0.3 引脚拆成四块 STM32 的独立固件。旧 `node_a.c` / `node_b.c` 保留不动，本目录是新的四节点目标代码。

## 范围

**已实现**

- 按 `BOARD_ID=1..4` 选择板型，四板共用同一套代码
- 每板只初始化本区传感器，采集：MQ-2（DO）、MQ-4（AO）、CO/MQ-7（AO）、火焰（DO）、液位（DO）、SHT3x（软件 I²C）、氧气裸探头（AO）
- 数字量低有效、4 次去抖；模拟量 64 次平均、239.5 周期采样
- Modbus RTU 从站：19200、8E1，功能码 03/04，固定 52 个输入寄存器
- USART1 调试日志（115200 8N1）

**未实现（后续版本）**

- 屏幕、摇杆、菜单
- 风机 PWM/TACH、继电器、蜂鸣器、WS2812
- 下行命令与回执
- INA226 电流/电压
- MQTT 上行（由 S3 网关完成）

## 引脚

见 `docs/hardware/four-controller-wiring-20261026/README.md`。本固件使用的关键引脚：

| 板 | 位置 | 检测站 | 传感器数 | 本板 I²C |
| --- | --- | --- | ---: | --- |
| 1 号 | 左下 | P3 + P5 | 11 | PB10/PB11 |
| 2 号 | 右下 | P4 | 7 | PB10/PB11 |
| 3 号 | 右上 | P2 | 6 | PB10/PB11 |
| 4 号 | 左上 | P1 | 7 | PB6/PB7 |

四块板统一：USART2 = PA2/PA3 接 485 模块；USART1 = PA9/PA10 调试；SWD = PA13/PA14。

## Modbus 寄存器

功能码 03 或 04，起始 0，固定 52 个寄存器：

| 地址 | 内容 |
| ---: | --- |
| 0 | 签名 `0x5554` |
| 1 | 板号 1～4 |
| 2 | 协议版本 `0x0100` |
| 3 | 有效传感器数量 |
| 4-5 | uptime 秒（高/低 16 位） |
| 6 | 采样序列 |
| 7 | 保留 |
| 8 + 4×i | 传感器编号（空槽 `0xFFFF`） |
| 9 + 4×i | 主值：DO 0/1；MQ 原始 ADC；SHT 温度（0.01 °C） |
| 10 + 4×i | 辅助值：SHT 湿度（0.01 %RH）；氧气毫伏；其他 0 |
| 11 + 4×i | 状态：0=ok，1=missing，2=suspect |

i = 0～10，对应本板传感器数组顺序。空槽编号为 `0xFFFF`。

## 构建

```powershell
# 从仓库根目录，把 N 换成 1～4
cmake -S firmware/four-controller -B build/four-N -G Ninja -DBOARD_ID=N
cmake --build build/four-N
```

输出 `build/four-N/four_ctrl0N.bin`，写入地址 `0x08000000`。

## 烧录后确认

USART1（PA9/PA10）115200 8N1：

```text
FOUR_CTRL CTRL-01 BOOT sensors=11 bus=PA2/PA3 19200-8E1
FOUR_CTRL CTRL-01 board=1 sensors=11 seq=3 uptime_s=7
```

S3 网关需要读取 52 个寄存器（签名 `0x5554`），现有的 `rs485-bench` 诊断程序只读 8 个寄存器、期望签名 `0x4853`，不能直接用于业务固件验证。

## 注意

- 本固件只读传感器，不驱动风机、继电器、蜂鸣器、灯带或屏幕，上电这些外设保持默认状态。
- 氧气裸探头是毫伏直连，状态固定为 `suspect`，不声明已标定浓度。
- MQ 原始 ADC 不是 ppm；四板各自采集，不做跨板联动。
- 四板共用一条 485 总线，终端仍按 GW-01 和 1 号开启，2/3/4 关闭。
