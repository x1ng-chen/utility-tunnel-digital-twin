# KK_UI 应用模型

## 开始具体功能前

完成 KK_UI 移植只代表运行环境可用，不代表用户已经确定具体产品界面。用户需求还不明确时，先用自然语言讨论真正会影响实现的内容：

- 首页需要哪些入口，以及页面和菜单之间的层级关系。
- 每个菜单项用于进入页面、执行操作、编辑整数、切换开关还是请求确认。
- 动态数据从哪里取得，哪些修改需要持久化或产生业务事件。
- 自定义页需要响应哪些输入，以及用户如何退出。
- 操作完成、失败或需要确认时采用 Toast、消息框还是确认框。

只询问会改变实现结果的关键问题，并可以结合内置能力提出少量合理选项；不要要求用户先理解页面 ID、描述表或字体资源等实现细节。形成可执行的页面与交互方案后再修改应用清单和业务代码。

## 静态描述

应用长期持有一个 `KK_UI_App`。路由数组的第 0 项对应页面 ID 1；页面 ID 0 无效。首页、菜单、信息页和自定义页分别引用各自类型表的索引。

菜单项 `ref` 解释规则：

| 类型 | `ref` |
|---|---|
| `KK_UI_MENU_PAGE` | 目标页面 ID |
| `KK_UI_MENU_ACTION` | 业务事件 ID |
| `KK_UI_MENU_INT` | 整数绑定表下标 |
| `KK_UI_MENU_BOOL` | 开关绑定表下标 |
| `KK_UI_MENU_CONFIRM` | 确认描述表下标 |

非根菜单自动追加返回项。动态状态表每项 2 bit：`00` 正常、`01` 隐藏、`10` 禁用、`11` 保留并按禁用处理；需要 `(item_count + 3) / 4` 字节。

## 变量与事件

整数绑定由标题、`int32_t *`、闭区间最小/最大值、固定步长、单位和修改事件构成。开关绑定由标题、`bool *` 和修改事件构成。指针必须长期有效。

事件只是 `uint16_t` ID。应用主循环持续调用 `KK_UI_PollEvent()`，完成持久化、外设修改、动态字符串更新和后续 Toast/消息。事件 ID 0 表示不发送。不要在描述中保存短生命周期字符串。

队列满时编辑提交、确认动作和自定义页完成均保持原状态；应用应及时取空事件队列。

## 自定义页

应用统一提供 `OnEnter`、`OnLeave`、`OnInput`、`OnTick`、`OnDraw` 五个固定符号，并按页面 ID 分派。页面自身状态使用项目静态变量。

- 输入已经标准化为上/下/确定、步数和来源。
- `OnTick` 返回是否需要重画。
- `OnDraw` 尊重 `x_offset`、`clip_x` 和 `clip_width`；需要主动设置字体与绘图模式，结束前恢复裁剪。
- 使用 KK_OLED 绘图或 `kk_ui_draw.h` 的无状态辅助；不得清屏或提交刷新。
- 在适配函数中发起的弹框、Toast 和关闭请求会在返回后执行。
- `KK_UI_CustomFinish(event)` 只在事件成功入队后离开页面。

自定义页不能继续压入自定义页。确实需要多层业务流程时，在一个自定义页内部维护轻量步骤状态，或重新评估页面结构。

## 输入语义

同轮优先级为确定键、编码器、方向键。编码器正值对应下/增加，负值对应上/减少，多档直接更新最终目标。普通按键由 KK_UI 去抖和连发；上、下同时按下抵消，确定键不重复。

## 字体检查

收集首页标签、菜单标题和条目、单位、弹框、Toast、信息行名称和值、自定义页文字以及动态值可能出现的全部字符。调用字体 Skill 生成项目专用子集，并沿用目标工程已有方式检查真实字形和排版。
