# KK_UI 使用

只在项目应用层描述 UI，保持 KK_UI 核心和刷新所有权不变。

## 工作流程

1. 检查工程状态和实际 `kk_ui.h`、应用清单、字体、图标、业务变量与事件处理；以项目现有副本为准。
2. 完整阅读 [application-model.md](references/application-model.md)。如果用户尚未明确页面结构、菜单行为、数据与操作或关键交互，先按其中的“开始具体功能前”与用户讨论；不要根据运行时示例猜测业务界面，也不要因为移植已经完成就直接开始功能开发。
3. 需求明确后，为需要的页面、菜单项、绑定和事件分配静态描述。刚完成移植时，在方案确认前保留已验证的最小应用，不用临时设想替换它。
4. 页面 ID 和事件 ID 使用非零 `uint16_t`；确保路由下标、页面引用、绑定引用和编译期开关一致。
5. 简单整数和开关使用内置编辑器。普通业务操作通过事件队列交给应用处理，不在 UI 核心中加入业务回调。
6. 运行时生成列表、波形或业务专用交互使用全屏自定义页。自定义页只维护应用静态状态并使用标准输入事件，不清屏、不刷新、不访问内部状态。
7. 动态文字、状态表和变量由应用长期持有。修改后调用 `KK_UI_Invalidate()`；需要“事件成功才离开”时使用 `KK_UI_CustomFinish()`。
8. 收集全部可见文字；缺字或需要压缩字体时使用 `kk-oled-font`。项目图标和业务资源留在应用层。
9. 沿用目标工程已有方式检查布局、交互和构建结果，说明已完成与待验证内容，不强加固定测试或运行工具。

## 边界

- 不修改 KK_UI 公共 API、核心状态机或内置页面布局来满足单个页面的特殊效果。
- 不建立动态菜单容器、通用控件树、任意回调表或堆分配。
- 内置模板和自定义页都无法合理完成需求时停止实现，给出不足证据和资源估算，转入 `kk-ui-extend` 的严格评估；未经明确同意不扩展核心。
- MCU、总线、OLED 控制器、刷新模式或分辨率适配使用 `kk-ui-port`；KK_OLED driver 问题使用 `kk-oled-port`。
