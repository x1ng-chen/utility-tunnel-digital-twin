# KK_OLED 应用语义

以下内容是常见当前契约。实现前仍应以目标工程实际的 `kk_oled.h` 和源码为准；若副本已经演进，应沿实际调用关系确认差异。

## 帧与刷新

- 每帧从空白绘制缓冲区重画完整场景。差分发送只优化总线流量，不是只画变化区域的应用接口。
- 成功提交后交换显示/绘制缓冲区，并清空新的绘制缓冲区。
- 阻塞刷新返回 `OLED_OK` 时，传输与提交已经完成。
- IT/DMA 刷新返回 `OLED_OK` 时，只表示异步传输已启动，或空差异帧已立即提交。之后通过 Busy 和最终状态接口判断完成或错误。
- Busy 期间可以继续绘制下一帧，但不能再次刷新，也不能执行会发控制命令的操作。不要排队或循环重入刷新。
- 异步失败后保留正在绘制的下一帧；下一次正常刷新应由库的恢复语义强制全屏发送。应用不要私自清理内部状态。
- 休眠与唤醒要尊重稳定帧恢复流程，不把“内存中有稳定帧”描述成“屏幕已经完整显示”。

优先的异步方式返回 `OLED_UNSUPPORTED` 时，应用可以明确回退到另一种受支持方式或阻塞刷新；只回退一次，避免每帧重复试错。

## 坐标、裁剪与旋转

- 所有布局使用运行时逻辑宽高，不把物理宽高写死。90°/270° 旋转会交换逻辑宽高。
- 裁剪窗口通常采用半开区间 `[x, x+w) × [y, y+h)`；改变旋转后重新建立需要的自定义裁剪。
- 坐标、尺寸和计算中间值必须符合实际 API 类型；先扩大类型完成加减乘，再安全收窄。
- 零尺寸图元应作为无操作；越界部分交给裁剪，避免应用侧发生无符号下溢。
- 前景绘图模式控制置位、清除或 XOR。背景模式独立控制文字和 XBM 的 0 像素；不要混淆两者。

## 图元与 XBM

- 根据目标公共头文件选择已有图元，不通过调用内部函数补齐应用效果。
- XBM 数据按行排列，字节内 LSB-first。确认数组宽高、锚点和背景模式与目标接口一致。
- 旋转位图的锚点必须位于源图内部；动画中保持资源生命周期覆盖所有绘制调用。

## 文字

- 调用文字接口前设置有效字体。字体指针必须在整个使用期间保持可访问。
- 默认文字坐标通常是 baseline；Top、Bottom、Center 和参考高度设置会改变 Y 坐标含义。布局前显式设置所需状态。
- `OLED_DrawUTF8` 的返回值是全部字符的 advance 总和；`OLED_GetUTF8Width` 是可见宽度，两者不能互换用于右对齐或光标推进。
- 当前解码器只支持 Unicode BMP。合法非 BMP 字符和畸形 UTF-8 的替代行为要向用户说明。
- 缺字通常不绘制像素，并采用空格 advance；如果字体也没有空格，advance 可能为 0。不要把缺字误判成刷新故障。

## 主循环组织

典型非阻塞循环先处理完成状态，再在可绘制时构建完整下一帧，最后仅在非 Busy 时启动一次刷新。动画时间推进与传输完成解耦时，应定义丢帧或保留最新帧的策略，不能在 Busy 分支中反复提交。
