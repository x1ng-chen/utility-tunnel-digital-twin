# KK_UI 移植验证清单

沿用目标工程已有的编译、测试、运行和验收方式，从下面选择适用项目。此清单不规定语言标准、工具链、构建配置名称或硬件工具；暂不可执行的项目记录为待验证，不作为开始 KK_UI 移植的前置条件。

## 静态与构建

- 按工程实际采用的语言标准、编译器和构建系统接入；遇到兼容差异时做最小适配并说明，不因工具不同拒绝移植。
- 构建与任务有关的现有配置，确认启用和关闭模块时的源码、宏与链接结果符合项目预期。
- 工程已有资源分析能力时，区分 KK_UI 核心、字体、图标、应用资源和 KK_OLED 缓冲。
- 确认没有因 KK_UI 意外引入动态内存或不必要的格式化依赖。
- 工程已有栈分析方式时，检查新增路径不存在不可接受的栈峰值。

## 自动化与模拟验证

目标工程适合执行时检查：

- 页面路由、深层导航、返回恢复、栈满、动态状态与焦点修复。
- 整数极值/边界/取消、开关幂等、事件 FIFO 和队列满原子性。
- 启动按住、去抖、连发、多键、编码器多档、输入优先级和时间回绕。
- 自定义页生命周期、延迟请求、防重入以及完成事件入队后才关闭。
- 用比目标帧间隔更短和更长的异步传输时间验证发送帧冻结、Busy 重画和最新帧提交。
- 启动失败、完成失败、超时、恢复后强制重画。

## 目标运行与显示

条件具备并符合目标工程工作方式时检查：

- 按项目已有方式加载并运行程序，检查启动过程。
- 逻辑方向、首尾像素、裁剪和控制器偏移。
- I2C/SPI 实际时序；IT/DMA 回调、Busy 状态和故障恢复。
- 三键按下/释放/连发；编码器方向、快速旋转和按压时轻微转动。
- 所有实际中文、ASCII、单位和动态值无缺字。
- 首页、菜单、转场、弹框、Toast 在真实刷新速度下连续且无撕裂。

报告时说明每项结论的证据来源，区分已经执行和仍待验证的内容。一个层面的结果不能代替另一个层面，也不能因某项暂不可执行而否定或停止其他工作。
