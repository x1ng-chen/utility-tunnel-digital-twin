# KK_UI 移植策略

## 1. 先确认显示契约

KK_UI 正式运行时只面向通过像素亮灭绘制画面的 1 bit 单色图形 OLED。面板发光颜色不改变 UI 数据模型；灰度、多色或非页式 framebuffer 不能当成普通布局移植。

先从目标工程与 KK_OLED 源码确认：

- 旋转后的逻辑宽高、裁剪坐标和位图格式。
- 控制器可见区域、列/页偏移已经由 KK_OLED driver 处理。
- blocking、IT、DMA 中哪些是真正实现而非同步替代。
- `OLED_IsBusy()`、最终完成状态和恢复流程。
- 异步发送时是否冻结独立发送缓冲，绘制缓冲是否仍可安全修改。

OLED 控制器、地址、总线、DMA 和回调不属于 KK_UI。相关事实不清楚时先用 `kk-oled-port` 确认或修复。

这里要求理解的是 KK_UI 当前接入所涉及的数据布局和刷新契约，不要求 KK_OLED 在移植 KK_UI 前先显示检测画面。沿用目标工程已有的开发与验证方式；某项验证暂时无法执行时，完成其余可确定的接入并将该项留待后续。

## 2. 安装与已有副本保护

资产 `assets/kk-ui-runtime` 是经过验证的可编辑快照。首次安装时将它复制到工程自身源码树并加入构建。复制后工程副本归项目所有。

如果目标目录已经存在：

1. 列出双方文件并比较内容。
2. 识别目标工程新增、删除和修改的文件。
3. 向用户说明需要保留和需要更新的差异。
4. 只对明确范围做增量修改。

不得递归覆盖目标目录，不得把 Skill 资产目录设为工程 include/source 路径，也不得假设版本号相同就没有本地修改。

## 3. 128×64 参考接入

参考布局使用 32×32 首页图标、三图标视口（两侧各显示一半）、一行反相标签、普通菜单三条可见行和顶部标题。编译期默认导航深度 8、事件队列 4、20 ms 帧间隔、20 ms 去抖、450 ms 首次重复、250 ms 显示超时。

接入时：

- 只编译 `include` 和 `src` 的正式运行时，不把历史 Demo 源码加入固件。
- 项目拥有 `KK_UI_App`、动态状态表、绑定变量、事件处理和五个自定义页适配符号。
- 使用构建宏选择刷新模式和裁剪模块，不修改公共头文件来保存每个工程的构建差异，除非工程本身采用项目配置副本策略。
- 更新函数至少每 10 ms 调用一次，不能由 20 ms 绘制间隔反过来限制输入采样。

## 4. 其他主流尺寸

不机械等比例缩放 128×64 坐标，也不向核心加入自动响应式布局。以可读性和交互语义为优先，在目标工程副本内集中调整绘制常量。

### 128×32

- 优先取消或压缩标题栏；普通菜单通常保留 2 行而不是强塞 3 行。
- 首页图标建议改为 16～24 px，并重新确定两侧半图标的可见宽度。
- 对高度无法容纳的三段式编辑框，改为全屏编辑页或减少信息层级。
- Toast 和焦点框必须重新检查基线、圆角和底部边界。

### 64×48

- 首页不必维持 32 px 图标；离线重制 16～24 px 图标，避免运行时缩放。
- 菜单标题、名称和值必须分别测量宽度；必要时减少可见行或隐藏次要值。
- 页面转场偏移按逻辑宽度重新选取，裁剪窗口不能沿用 128 px 假设。
- 长中文通常应改短标签或使用业务自定义页，不引入运行时跑马灯作为普遍补丁。

### 其他尺寸

逐项决定标题高度、字体、行高、可见行数、首页图标、边距、弹框区域、按钮宽度、滚动条和转场偏移。尺寸不足时弹框可变为全屏。为目标尺寸离线生成字体子集与图标，验证每个实际文本，不在 MCU 运行时缩放字体或位图。

当某一适配只服务单个项目时保留在项目副本。只有多个项目证明其可复用性、完成资源评估并获得明确同意后，才转入 `kk-ui-extend` 评估。
