# 移植验证

根据目标工程实际提供的构建和测试入口选择层级，不照搬其他仓库的命令。

开始修改具体 driver 前，先向用户展示已确认事实及来源、仍未知的关键事实，以及阻塞、IT、DMA 的当前配置与可选项。初始化、寻址和时序等细节应优先从已确认的芯片与模组资料推导，不要求用户逐项回答。关键事实仍未知时，只询问未确认且会影响正确性的项目；不能用常见值完成构建后声称移植成功。

## 1. 静态与构建

- 检查编译源、include 路径、宏和 SDK 生成文件确实纳入目标构建。
- 用户选择启用 IT/DMA 时，检查工程配置事实来源、生成产物、中断/DMA 映射、句柄和回调保持一致，重新生成后修改不会丢失。
- 启用工程可承受的警告，并确认无隐式声明、指针/长度截断或未处理返回值。
- 检查每个宽高、页数、传输长度和 buffer 索引的类型上限。
- 保留并报告用户已有的未提交修改，不顺手格式化或改写无关文件。

## 2. 主机或假传输测试

工程允许时，记录并断言：

- 初始化顺序、地址表示、命令/数据区分和列偏移；
- 每页脏区的起止列及传输长度；
- 空差异、边界页和全屏传输；
- IT/DMA 启动、Busy、分阶段完成、启动失败和异步错误；
- 完成通知只发生一次，失败后下一次正常刷新能够全屏恢复。

假 HAL、mock 总线或逻辑分析仪只能证明字节和状态机符合预期，不能证明屏幕视觉正确。

## 3. 目标构建与烧录

- 使用目标工程已有的 Debug/Release、链接脚本和生成流程。
- 分别报告编译、链接、资源占用以及是否实际烧录。
- 只有用户已授权烧录并且目标设备明确时才执行；烧录成功不等于显示验收通过。

## 4. 实物验收

至少检查初始化无随机画面、边缘/列偏移、完整图案、文字、阻塞刷新，以及已实现的 IT/DMA 动画和错误恢复。把肉眼观察、照片或仪器证据与 `OLED_OK`、总线 trace、编译成功分开陈述。

最终交付列出：改动文件、已确认硬件事实及来源、仍未知的硬件事实、用户选择的 IT/DMA 方案、实际支持的传输方式、每层验证结果、未验证项和剩余风险。
