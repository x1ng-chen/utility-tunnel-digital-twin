# Driver contract

## 事实优先级

目标工程的公共头文件、内部头文件和现有 driver 是当前版本的最终依据。下面描述的是兼容性基线；若目标副本已经演进，应根据实际调用关系重新确认契约，不要强行回退。

## 图形核心兼容门槛

普通 driver 移植必须同时满足：

- 显存为 1-bit 单色页布局，每页覆盖 8 个垂直像素；物理高度必须是 8 的倍数。
- 物理宽度能由当前脏区最小/最大 X 索引表示；索引为 `uint8_t` 时，宽度不得超过 255。
- 页索引不能溢出其实际类型；页索引为 `uint8_t` 时，页数不得超过 255。
- `width * (height / 8)` 不得溢出实际 buffer 索引类型；索引为 `uint16_t` 时不得超过 65535。
- 公共逻辑尺寸必须能由其实际坐标类型表示；坐标为 `int16_t` 时，单边不得超过 `INT16_MAX`。
- 目标控制器能够按核心提交的页和列区间写入数据。控制器命令格式、寻址模式或灰度布局不同并不自动兼容。

不满足任一项时，停止把任务描述为“只改 driver”，列出所需核心数据结构或公共契约改造，等待用户明确扩大范围。

## 目标副本中的接口

先追踪实际声明和调用点。常见 driver 契约包括：

- `OLED_DriverInit`
- `OLED_DriverWriteBlocking`
- `OLED_DriverWriteIT`
- `OLED_DriverWriteDMA`
- `OLED_DriverIsBusy`
- `OLED_DriverSetContrast`
- `OLED_DriverSetPowerSave`
- `OLED_DriverHandleMemTxComplete`
- `OLED_DriverHandleError`

常见内部传输契约包括：

- `OLED_InternalGetTransferBuffer`
- `OLED_InternalGetTransferMinX`
- `OLED_InternalGetTransferMaxX`
- `OLED_InternalTransferFinished`

名称或签名不一致时，以目标工程为准，并检查每个调用方，不要为匹配此列表而改公共 API。

## 阻塞与异步

- 阻塞刷新必须可用，成功返回时传输和提交均已完成。
- IT/DMA 启动成功后保持 Busy，直到对应完成或错误事件结束；完成通知必须恰好一次。
- 启动失败和异步错误都必须释放 driver 状态，并把真实错误交还核心恢复逻辑。
- DMA 使用的源缓冲区在完成前必须保持冻结；不得发送仍可被应用绘制修改的缓冲区。
- SDK 缺少真正的 IT/DMA 能力时返回 `OLED_UNSUPPORTED`。不要立即调用完成回调，也不要在异步接口内偷偷阻塞。
- 应用回调只转发属于本显示实例的完成和错误事件。不要在库中定义会接管整个 SDK 的全局弱回调。

## 硬件适配

从原理图、数据手册、生成配置和现有代码确认下列事实：

- I2C 地址是 7 位、8 位写地址还是 SDK 特有表示；只在调用边界做必要转换。
- SPI 的 DC、CS、Reset 极性与时序，以及命令和数据的分段方式。
- 初始化命令、寻址模式、页命令、列高低位、可见列偏移和休眠/唤醒顺序。
- 总线单次传输上限、DMA 可访问内存区域、对齐、缓存维护和回调上下文限制。

不要把上述清单原样变成向用户提问的问卷。先从工程和可靠资料中自行确认，并依据已知的控制器与模组资料推导初始化序列、寻址方式和时序等实现细节。

控制器型号、物理分辨率、总线与地址/片选方式、必要的列/页偏移等关键事实在检查后仍无法确认时，只向用户询问这些未知项，并说明它会影响的参数或兼容性判断。在取得可靠依据前，不要猜测或填写硬件相关参数。用户也无法确认时，先请求模组型号、购买链接、丝印/排线照片、原理图或数据手册，再给出识别办法；I2C 扫描结果只证明某地址有响应，不能据此推断控制器型号、地址表示、分辨率或偏移。

## 可选外设能力

在移植前确认中说明阻塞、IT 和 DMA 的当前配置状态。若 MCU 与 SDK 支持 IT/DMA，但工程只因外设配置尚未开启而不能使用，应询问用户是否启用；不能直接判定为永久不支持。用户选择启用后：

- 修改工程真正的配置事实来源，例如外设配置文件、生成配置或手写初始化，而不是只修改会被重新生成覆盖的产物；
- 确认中断向量、DMA 通道或请求映射、优先级、句柄关联、回调归属和 DMA 缓冲限制；
- 重新执行工程已有的代码生成、构建和验证流程，并检查未覆盖用户的其他外设配置。

用户不需要 IT/DMA 或平台确实不支持时，可以保留阻塞实现并让相应入口返回 `OLED_UNSUPPORTED`。

不要把参考实现和常见模组值当作候选默认值写入代码，也不要猜测初始化值、引脚极性或 SDK 句柄。

确认后的固定参数应留在具体 driver 内，而不是扩展成运行时控制器数据库。

## 受保护边界

除非用户明确要求并接受范围扩大，否则不要修改：

- graphics 中的像素布局、裁剪、双缓冲和提交状态机；
- 对外公共函数、状态码和对象模型；
- 与当前移植无关的字体、图元和应用业务逻辑。
