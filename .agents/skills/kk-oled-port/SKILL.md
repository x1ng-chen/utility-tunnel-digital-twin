# KK_OLED 移植

把用户工程中的实际代码和硬件资料作为事实来源，不把内置参考 driver 的平台、目录或参数套到目标工程。

## 工作流程

1. 在修改前发现工程中实际的 `kk_oled.h`、graphics、driver、构建文件、应用入口和已有本地修改。优先使用高效的文件搜索和版本控制状态；没有版本控制时也要先建立文件清单。
2. 若工程已有 KK_OLED，以该副本的公共头文件、源码、版本和本地修改为事实来源，不用内置源码覆盖、合并或回退它。
3. 若工程尚未包含 KK_OLED，使用 [assets/kk-oled-runtime](assets/kk-oled-runtime/) 建立一个可编辑的项目副本。先依据工程现有资源组织、模块边界、命名和构建方式选择合适位置；无法判断时询问用户，不擅自规定项目结构。复制运行时源码并保留 MIT 许可证，不把已安装 Skill 的资产目录直接作为工程构建输入。
4. 内置 `driver/` 是 STM32 HAL、I2C1 和 CH1116 的参考实现，只用于提供真实的 driver 契约与异步状态机起点。不要把其中的控制器、分辨率、地址、句柄、列偏移或初始化序列当作目标工程默认事实。
5. 根据当前移植范围，从源码、芯片配置、原理图、数据手册和用户资料中确认所需硬件事实。优先自行检查工程和资料，不把 MCU/SDK、控制器、物理宽高、I2C/SPI、地址及其表示方式、引脚、初始化与寻址、列/页偏移、传输限制、IT/DMA 约束和 RAM 预算整理成问卷交给用户。
6. 在修改具体 driver 前执行下面的“移植前确认”，然后完整阅读 [driver-contract.md](references/driver-contract.md) 并做兼容性判断。不满足图形核心的数据布局和索引上限时，明确说明需要核心改造及原因，不把它伪装成普通 driver 移植。
7. 默认只修改目标工程的具体 driver、硬件参数、外设配置、构建接入和应用回调。保留已有工程约定与本地修改。未经明确要求，不修改 graphics、双缓冲/提交语义或公共 API。
8. 实现并验证阻塞传输。按用户在移植前确认中的选择实现 IT/DMA；用户选择启用且硬件与 SDK 支持时，负责补齐外设配置、驱动代码和回调接线。用户不需要或平台不支持时，相应入口返回 `OLED_UNSUPPORTED`。不要用阻塞调用冒充异步支持。
9. 维持单实例、固定 driver 的轻量结构。不要新增总线抽象、控制器表、函数指针表、公共对象句柄或运行时注册机制。
10. 按 [verification.md](references/verification.md) 分层验证，并分别报告静态检查、构建、主机测试、烧录、总线观测和实物显示证据。未执行的层级要明确标注。

## 移植前确认

开始硬件相关修改前，向用户展示一次简短确认，内容分为：

- **已知信息**：列出已确认的控制器、分辨率、总线、地址或片选方式、必要偏移、MCU/SDK，并标明来自工程、原理图还是数据手册；
- **待确认信息**：只询问仍未知且会影响正确性的关键事实；
- **可选能力**：说明工程当前的阻塞、IT 和 DMA 状态。

如果没有待确认信息或可选能力需要用户选择，展示后继续即可，不要求用户做形式化确认。有关键未知或存在是否启用 IT/DMA 的选择时，等待用户回答后再实施对应方案。

### 关键硬件事实

修改具体 driver 前，至少要有可靠依据确认那些决定控制器协议和可见区域映射的关键事实：

- 显示控制器的准确型号，以及已知的模组板级接线或地址配置；
- 物理分辨率、1-bit 页式显存兼容性和可见区域映射；
- 所用总线及实例；I2C 必须确认设备地址和目标 SDK 需要的 7 位/8 位表示，SPI 必须确认 DC、CS、Reset 的接线、极性和时序；
- 目标模组所需的列/页偏移或其他固定映射参数。

先用已确认的控制器和模组资料推导初始化序列、寻址命令及时序等实现细节，不要求用户逐项提供。只有关键事实经过工程与资料检查后仍无法确认时，才把未知项及其用途简洁列给用户询问；与当前实现无关或能从可靠资料确定的细节不要问。用户也不确定时，请其提供屏幕模组型号、购买链接、丝印/排线照片、原理图或数据手册，再给出识别办法。

不要拿参考 driver 或常见模组参数补空白，包括但不限于 CH1116/SSD1306、`0x3C`/`0x3D`、128×64、列偏移 0/2、`hi2c1` 和任意通用初始化表。在关键事实取得可靠依据前，不得把猜测写入硬件相关 driver。I2C 扫描最多能确认某地址有设备响应，不能单独证明控制器型号、地址表示、分辨率或列偏移。

### IT 与 DMA 选择

阻塞刷新始终是必选基线。检查 MCU、SDK 和工程配置后：

- IT/DMA 已可用时，按用户需求接入并验证；
- 硬件与 SDK 支持但工程只是尚未开启时，向用户说明启用后的作用、需要修改的外设配置和回调，再询问是否使用；
- 用户选择使用后，修改工程实际的配置事实来源并按现有生成流程更新代码，补齐中断、DMA 通道/请求、优先级、句柄和回调接线；不能只改随后会被生成器覆盖的文件；
- 用户不使用或平台不支持时，保留阻塞刷新，并让未实现的 IT/DMA 入口返回 `OLED_UNSUPPORTED`。

若需求实际是界面绘图、动画或刷新组织，改用 `kk-oled-use`；若需求是缺字、字体子集或字体 Flash 优化，改用 `kk-oled-font`。
