# KK_UI 扩展准入与复核

## 准入结论必须回答

1. 哪个已确认需求无法由内置模板或自定义页合理完成？
2. 为什么应用级实现会导致明确的重复、错误风险或不可接受的资源成本？
3. 至少哪些页面或项目会复用新能力？
4. 最小公共 API 和状态是什么？能否改为纯无状态绘制辅助？
5. 完整功能与关闭模块时分别增加多少代码空间、静态存储和栈？
6. 如何避免额外 framebuffer、堆分配、任意回调表和重入？
7. 用户是否已经明确同意修改核心或公共 API？

任一项没有可信答案时停止核心实现，回到应用自定义页或继续讨论。

## 设计复核

- 状态只为互斥生命周期保存一次，静态描述优先位于只读存储区。
- 输入仍通过标准化事件进入，刷新仍由 `KK_UI_Update` 唯一提交。
- 时间驱动动画允许跳帧，不建立帧队列。
- 公共类型不暴露内部状态或 framebuffer，不引入通用 `void *` 载荷。
- 错误和业务事件边界保持明确，队列满操作具有原子性。
- 新功能关闭后不要求应用提供无意义符号，符号表能证明实现被裁剪。

## 验证复核

- 为起点、中间和终点建立可解释的 framebuffer 验证；只在几何确实变化时新增金样。
- 增加正常、边界、取消、连续输入、时间回绕、队列满和显示故障用例中适用的部分。
- 使用目标工程已有的相关构建、告警和运行期检查，不额外规定编译器、检查器或配置名称。
- 按工程已有资源分析方式对比扩展前后的代码空间、静态存储和最大栈，并把字体、图标与核心成本分开。
- 目标显示效果尚未验证时明确列为待办，不能用预览图替代。
