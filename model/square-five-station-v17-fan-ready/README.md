**已完成模型叶轮拆分与合成遥测验证；尚未连接实物或接入运行网页。**

## 已完成

- 在 V16 的两台风机下新增 `FAN-01_ROTOR`、`FAN-02_ROTOR`，各自包含轮毂和五片叶片，转轴经过风机中心。

- 700×700×300 mm 布局、69 个语义资产、31 个独立传感器、五站分组均承接 V16。现有网格及静止姿态通过导出前后比较，浮点矩阵容差为 1e-6。
- GLB 共 693 个节点，比 V16 增加两个空父节点；没有自动播放动画。平台应按状态逐帧驱动叶轮。
- 原 V16 原生文件、V16 GLB 和运行网页 GLB 的 SHA256 均保持不变。

## 文件

`square-five-station-v17-fan-ready.blend` 是可编辑原生文件，`square-five-station-v17-fan-ready.glb` 是完整模型。

`fan-animation-contract.json` 给出两台风机的节点、中心、Blender/GLB 旋转轴和遥测规则。GLB 使用米和 Y 向上坐标，不能直接套用 Blender 的 Euler Y 轴。实际加载检查已验证合同中的局部轴。

`fan-motion.mjs` 是独立的 Three.js 接入参考，当前网页没有导入它。它使用现有渲染循环、帧间时间和单独的叶轮节点；提供清理接口，模型替换后需要销毁旧控制器。新模型不包含自动启转的关键帧。

`asset-map.json/.csv`、`sensor-bindings.json`、`station-focus.json` 承接 V16；风机资产另有 `rotorNode` 属性。模型身份连续性仍不代表全部真实台账已核实。

## 后续实际联动规则

现有 `DashboardView.vue` 已读取两台风机各自的 `rotational.speed`；`TwinScene.vue` 目前接收资产和告警，尚未接收风机遥测。下一步需要将新模型与转速读数接入三维页。

| 输入 | 三维行为 |
| --- | --- |
| 对应风机、质量 good、时间有效且新鲜、单位 rpm、转速大于 0 | 只旋转对应叶轮 |
| 同样有效的新鲜转速为 0 | 停在当前角度，显示已停止 |
| 无读数、过期、质量异常、离线、时间错误或演示数据源 | 冻结并显示状态未知 |
| 仅收到启动/停止指令回执或 PWM 设定 | 不据此认定实物已转/已停 |

继电器断电后风机可能惯性滑行，应继续跟随有效转速，直到反馈归零。若未来只有可靠的运行状态而没有转速，只能实现明确标注的示意旋转；不能将示意速度当成实测转速。

两台风机在模型和读数上分别处理。现有代码中有共享继电器使能、分别 PWM/TACH 的历史说明，本轮未验证四主控新版的实际接线，不据此保证两台实物可以独立通断电。

参考实现要求明确传入 `maxAgeMs`；应根据真实采样周期、传输抖动和设备时钟制定。测试中的 3000 ms 仅为合成样例，不是生产超时配置。界面示意转速上限 90 rpm 是防止高速频闪的可调显示选择，界面仍须单独展示实测转速。正反转方向也尚未与实物核实。

## 验证及边界

`model-readiness-report.json`：MCP 建模、叶片绕轴、外壳固定、静止姿态比较、保护文件哈希。

`native-verification.json`：隔离 Blender 进程重新打开原生文件，核对 69 资产、31 传感器及两台独立叶轮；验证进程没有保存模型。

`glb-animation-verification.json`：使用项目已安装的 Three.js 实际加载 GLB，32 项检查通过，包括独立启停、归零停转、重新启动、过期/离线冻结、坏质量、乱序与冲突数据、30/60 帧一致性和销毁控制器。输入全部是合成数据；这不代表浏览器画面或实物联调已验收。

MCP 调用证据在 `mcp-evidence/`。准备与导出分两次调用，避免 Blender 重新打开文件后的旧 UI 上下文失效：依次执行 `prepare_fan_rotors.py` 和 `export_fan_rotors.py`。准备脚本会从保存的 V16 基线重新生成，人工修改前请另存文件。初期诊断失败保留在证据中，最终通过记录为 04 和 05。

继承的实物尺寸、孔位、装配、电源、散热和防溅等概念限制见随附 `layout-and-hardware-notes-v16.md`。本轮没有实物风机启动测试、固件修改、数据库写入、运行前端修改、模型上线或部署。
