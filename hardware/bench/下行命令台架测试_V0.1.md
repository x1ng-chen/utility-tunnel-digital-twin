# 下行命令台架测试 V0.1

> 状态：控制面、PB0 蜂鸣器和 Web 灯带下行闭环已完成真机验证（2026-09-02）。本用例验证当前 Node A（CTRL-01）与 ESP8266 的命令接收、超时、去重、回执，以及已冻结执行器的受限动作。

关联：GitHub #17、#18、#19。

## 前置条件

- CTRL-01 STM32 烧录 `NodeA` 镜像（`build/NodeA/stm32_controller.bin`），ESP8266-01S 烧录 `esp01_ctrl01`。
- 两者 USART2（PA2/PA3）交叉连接、共地，速率为 9600 bit/s、8N1。
- Node A 保持 SHT30 Slot 1（PB6/PB7）与已核验的 3.3 V 供电；MH-FMG 有源蜂鸣器接 PB0（I/O）、3.3 V（VCC）和共地（GND）。当前继电器为可选高/低电平触发的 5 V 模块，跳帽置 H 档：PA1→IN、5 V→DC+、GND→DC-；负载侧为 12 V 正极→COM、NO→风机正极、12 V 负极→风机负极。裁剪后的 9 颗 WS2812B 灯带由独立 5 V 电源供电，DIN 仅经 74AHCT/74HCT 电平转换接 PB15 / SPI2_MOSI。

## 命令格式

向 `ut/v1/CTRL-01/cmd` 发布 JSON（命令 ID 只允许字母、数字、`-`、`_`）：

```json
{"schema":"ut.command.v1","cmdId":"bench-status-001","action":"status","ttlMs":5000}
```

设备会向 `ut/v1/CTRL-01/cmd_ack` 返回 `ut.command.ack.v1`。当前允许的非执行器动作：

- `status`：返回 `accepted/controller_online`。
- `safe_state` 或 `buzzer_off`：立即使 PB0 输出低电平，返回 `accepted/buzzer_silent`。
- `buzzer_on`：仅驱动 PB0 高电平，鸣叫时长不超过 `ttlMs`，返回 `accepted/buzzer_active`；`ttlMs` 上限为 30000。
- `relay_on`：驱动 PA1 高电平吸合，时长不超过 `ttlMs`，返回 `accepted/relay_active`。
- `relay_off`：立即使 PA1 输出低电平释放，返回 `accepted/relay_off`。
- `led_red`、`led_green`、`led_blue`：以受限亮度统一点亮 9 颗 WS2812B；`led_off` 或 `safe_state` 使全部熄灭。
- 其他动作：返回 `rejected/actuator_unmapped`，不会改变任何 GPIO。

## 验收步骤

1. 记录 STM32 与 ESP8266 启动日志，确认 ESP 已订阅 `ut/v1/CTRL-01/cmd/#`。
2. 发布上面的 `status` 命令，保存命令与 `cmd_ack` 的 Broker 日志和串口日志。
3. 原样重复发布该命令，确认只收到 `duplicate/cmdId_seen`，且没有第二次动作。
4. 发布 `{"schema":"ut.command.v1","cmdId":"bench-relay-001","action":"relay_on","ttlMs":5000}`，确认收到 `rejected/actuator_unmapped`。
5. 紧邻发布两条不同的有效命令，确认每条各有一条 `cmd_ack`；Node A 的 UART 队列至少可缓存四条完整帧。
6. 发布 `ttlMs:0` 或超过 30000 的命令，确认收到 `rejected/invalid_or_missing_ttl`。
7. 发布 `{"schema":"ut.command.v1","cmdId":"bench-buzzer-001","action":"buzzer_on","ttlMs":1000}`，确认收到 `accepted/buzzer_active`，蜂鸣器鸣叫约 1 秒后停止。
8. 在触点侧无负载的前提下，发布 `{"schema":"ut.command.v1","cmdId":"bench-relay-002","action":"relay_on","ttlMs":1000}`，确认继电器吸合约 1 秒后自动断开；再以 `safe_state` 确认可提前断开。

通过本用例仅表示通信控制面可用。执行器 GPIO、电平、默认安全态和实体动作必须在引脚表冻结后另行验收，不能据此判定 M1 通过。

## 实测记录（2026-09-01）

- Node A 已通过 USB ISP 烧录并完成 Flash 校验；ESP8266-01S 已通过 USB-TTL 烧录并完成 Flash 摘要校验。
- 发布 `bench-status-001` 后收到 `accepted/controller_online`；原样重发后收到 `duplicate/cmdId_seen`。
- 单独发布 `relay_on` 后收到 `rejected/actuator_unmapped`，未接入或驱动任何执行器。
- 初次紧邻发布两条命令时发现 Node A 单帧 UART 缓冲会丢失后续帧；已改为四帧队列并重新烧录 Node A。
- 修复后紧邻发布 `burst-status-002` 与 `burst-relay-002`，分别收到 `accepted/controller_online` 和 `rejected/actuator_unmapped`。
- PB0 已冻结给高电平触发的 MH-FMG 有源蜂鸣器；Node A 已通过 USB ISP 写入并回读校验当前镜像。
- 发布 `buzzer-57a084d6487c`（`buzzer_on`，`ttlMs:1000`）后收到 `accepted/buzzer_active`；现场确认蜂鸣器实际鸣响。PB0 上电默认低电平，且固件在 TTL 到期、`safe_state` 或 `buzzer_off` 时保持/恢复静音。
- WS2812B 改用 PB15/SPI2_MOSI 的 DMA 连续编码发送；`led_green`、`led_red`、`led_blue` 与 `safe_state` 均收到对应回执。裁除原首颗后，新的首颗在红色命令下仍为绿色、后8颗红色；首像素RGB补偿未改变该现象，待核对数据是否误接DO侧或第二颗DIN，暂不判定为固件或器件故障。
- 项目方确认灯带在当前接法下可正常用于演示；上述首颗显示差异列为非阻塞观察项，不阻塞后续硬件联调。
- 2026-09-02：本机 Django API `POST /api/controllers/CTRL-01/commands/` 以运维员权限发布 `led_green`，服务端生成唯一 `cmdId` 并在 3 秒内收到 `accepted/led_green`；项目方现场确认灯带变绿。前端 Dashboard 的“灯带联调”面板仅提供红、绿、蓝、熄灭四个受限动作，完整操作写入审计。
- 2026-09-02：更换为 H/L 可选触发继电器并将跳帽置 H；Node A 改用 PA1。修复了命令处理前读取时间、导致定时执行器立即超时关闭的问题。`relay_on`（`ttlMs:10000`）收到 `accepted/relay_active`，现场确认继电器绿灯与 12 V 四线风机持续运行约 10 秒后自动停止。
- 本记录仍未覆盖风机 PWM 调速、RPM/TACH 反馈、断网恢复或连续运行验收。
