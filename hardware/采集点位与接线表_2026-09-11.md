## 1. 本轮要求与冻结边界

按用户最新要求，气体与水分别位于各自管道中，各类型的五个传感器分散采集，水测点需判断有水及低/高位。此前“全部环境传感器只测管廊空气”的假设不再作为本次建模依据。保留两台STM32、两台ESP8266及现有设备，不把新增候选当作已到货硬件。

FS-IR02数量按用户确认固定为5个，不增补。先完成本表、解决介质/水路形式与安装阈值，再改几何。当前模型不是本表的已实施版本。环形仅指几何形式，不代表所有测点共享同一个混合采样腔。

## 2. 能测什么，不能测什么

| 类型 | 每类数量 | 测量对象与安装原则 | 数据边界 |
|---|---:|---|---|
| MQ4 | 5 | 各自管段的独立取样支路与受控采样腔 | 先记录原始值，标定前不输出可信ppm/%LEL；不能直接暴露于未确认的高压/高浓度燃气 |
| MQ7 | 5 | 独立取样腔，和其他加热模块隔开 | 加热循环、有效采样窗口和标定尚需实现 |
| ME2O2 | 5 | 独立取样腔；保护电路与气体接触面分开 | 裸电化学元件必须匹配前端，不能将电流输出直接当3.3V AO |
| MQ2 | 5 | 独立取样支路；当前先保留DO阈值通道 | 是交叉敏感气敏元件，不能将管内可燃气响应自动命名为烟雾浓度 |
| SHT30 | 5 | 独立取样腔，避开MQ加热影响，核验凝露与介质相容性 | 温度/相对湿度；不当作接触式水温探头 |
| FLAME | 5 | 对应管段的外置光学观察位置，需明确可透过波段的视窗和视线 | 不穿透不透明管壁，不测气体浓度；未确认观察目标前不得假称采集管内火焰 |
| FSIR02 | 固定5，不增补 | 五个不同管段各一个探头，检测本地安装高度是否浸水 | 每处单阈值，不是连续水位，也不能每处同时独立判断低位和高位 |

管内真实介质和压力尚未确认。暂只允许以常压洁净空气做台架基线，异常使用既有隔离模拟盒；这不是用户已确认的介质。不得据本表将现有模块直接接入运行燃气管。

## 3. 水侧测量结构与判据

五个测站W1—W5属于不同管段，各自有本地液面基准，不能把五个不同地点的单点开关组合成一个水位高度。

仅使用现有5个FS-IR02，每个不同管段安装一个。安装高度需依据水路形式、内径和探头封装决定，不默认全部是低位，也不任填毫米值。若某点作为高位报警，该点只能报告“达高位/未达高位”；未达高位不能推出无水。若靠近管底用于有水检测，仍可能漏掉低于探头的残水。

| 探头状态 | 可报告内容 | 不可推导内容 |
|---|---|---|
| 浸水 | 该安装位置有水；在有效自由液面测量条件下已达到该点阈值 | 具体水位高度、另一个高/低阈值状态 |
| 未浸水 | 该安装位置未检出水；需排除气泡、污损和故障 | 整条管道绝对无水 |
| 故障/未核验 | 状态未知 | 不能当作干燥或正常 |

五处各自只有一个阈值，因此“每处独立识别无水、低位、高位”的完整目标在现有数量下无法同时满足，明确保留为能力缺口，不用软件生成缺失信息。若在五处选择不同安装高度，只能得到五个地点各自的阈值状态，不能合成为同一处的多档水位。不得将五个探头集中到同一根立管来回避分散测点要求。

非满管排水可检测局部液面是否达到安装位置。若是有压满管供水，应解释为局部浸水状态，不将开口水柱当作真实管内液位；不把开口测量腔直接接到DCP-3620有压出口。水路形式仍待确认。

raw电平先保存，再按逐只实测dry/wet映射归一化；现有固件PC0低有效，而供应商另一版本示例接触液体为HIGH，不能据型号统一极性。保留去抖、更新时间、质量标志。未实现线路诊断时，输入不变不能证明传感器在线。

## 5. 供电与接线原则

- MQ4/MQ7/MQ2：传感器/加热供电与MCU逻辑分开，继承15路驱动的计划数量；MQ7按具体型号手册实现高/低温循环，不把5V常热当作有效CO采集。前端缓冲、限幅、滤波后进入ADC；未知5V AO/DO禁止直连3.3V输入。
- ME2O2：裸元件接匹配的电流前端；若实物是带放大板套件，须先核对输出量程。五套各自标定，不共用一个未经校准的换算系数。
- SHT30：拟3.3V、GND、SCL、SDA四线，经MUX-01 CH0—CH4逐路选择，相同0x44地址每次仅开一路。多路开关不隔离电源、不消除长线电容；机柜内I²C短线优先，环向支线需实测上升沿/波形，失败则新增适配通信节点，不能直接套用建筑级长线。
- FSIR02：按现有5V板卡计划，DO经过核验的3.3V输入保护/转换后进采集端。AO不被当成连续水位。五个测点各有独立供电端子和信号编号，不再预留额外高位探头。
- FLAME、MQ2的DO：逐只验证供电、有效电平、输出形式，前端转换后接DI。采样管不能传递火焰的光学信息，火焰模块须有真实视线或明确模拟态。
- 线缆：气/水区只放适合该环境的探头与密封引出，裸板置于干区；模拟信号成对回流并与泵/风机电源线分槽。屏蔽接法、保险值、线径及保护参数经电流和接口审核后冻结，不能从模型推断。

## 6. 控制器保留与扩展板候选

CTRL-01保持Node A采集，CTRL-02保持Node B显示，不把显示板PB4—PB9再占给传感器。两台USART2 PA2/PA3各接自己的ESP8266；USART1 PA9/PA10用于调试，PA13/PA14保留SWD。

| 现有Node A资源 | 保留功能 |
|---|---|
| PB6/PB7 | I²C1；现有温湿度/电流总线，拟增加MUX |
| PB10/PB11 | I²C2；保留现有电流设备，拟接扩展前端 |
| PC1 / PC2 | 氧气1 / 甲烷1的ADC11 / ADC12 |
| PC0 / PB12 / PB14 | 液位1 / MQ2-1 / 火焰1 |
| PA6/PA7；PB8/PB9 | 风机1/2转速；PWM |
| PB0 / PA1 / PB15 | 蜂鸣器 / 继电器 / 灯带 |
| PC8 | 板载LED |

| 扩展资源 | 候选型号与地址 | 用途与状态 |
|---|---|---|
| MUX-01 | TCA9548A，I²C1 0x70 | 对应计划的1套I²C复用，具体器件未实装确认；迁移原SHT直连方案需改固件 |
| EADC-01—04 | ADS1115×4，I²C2 0x48/49/4A/4B | 16路单端，其中13路用于剩余气敏模拟信号，3路备用；是计划ADC前端的新增具体实现候选，不是已有4块板 |
| EDIO-01—02 | TCA9535×2，I²C2 0x20/21 | 32路可配置I/O；表中扩展12路DI，其余保留漏水/浮球/门磁与驱动控制；未采购未实现 |

撤销原高位探头分配，EDIO-02 P00—P04恢复未分配；两块扩展器仍为其他输入/加热控制的待评审候选，未经批准不采购。

备用分配：EDIO-01 P14/P15为LEAK1/2，EDIO-02 P05为FLOAT、P06为DOOR；MQ7五路加热模式控制预留EDIO-02 P10—P14，必须配实际高/低电压驱动与默认关闭电路，不可用扩展GPIO直接供热。扩展板数量、接口前端原理图与成本须评审后纳入BOM。

现有固件使用INA226（0x40，按总线区分），旧模型计划仍是INA219×1：保留差异待清单核定，不把两者当作兼容替换。本表不会覆盖现有固件或修改该数量。

## 7. 数据与验证

每条记录携带pointId、zone、pipeId、sensorType、source(real/simulated)、raw、normalizedValue、unit、quality、sampledAt、calibrationId。未标定MQ只上报原始量；FSIR02只上报wet及本地安装阈值定义，不生成虚假的level_mm。MQ7的更新受加热窗口限制；气路还必须记录取样延迟/吹扫完成，不能把上一个测点残气当作当前读数。

Node A → USART2 → ESP8266 → MQTT/后端 → Node B TFT/Web。现有单/少量测点协议需增加逐点编码、扩展驱动、超时与失效标志；本轮未做固件修改、烧录或实测。

验收顺序：确认介质/水路与五处安装阈值 → 原理图和针序审核 → 断电通断/短路检查 → 分级供电 → 单点原始值验证 → 多点唯一性/串扰检查 → 五个测点逐只干湿及失效测试 → MQTT逐点对照 → 最后按相同点位JSON改模型并进行管路/线缆/碰撞自审。
