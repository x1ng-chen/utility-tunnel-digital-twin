# 管廊运维 AI Agent 接入

平台登录后的页面右下角提供 DeepSeek 运维 Agent。它通过后端白名单工具查询资产、活动告警、最新遥测、近时指标统计、未完成工单和项目内部排查手册，返回工具轨迹及带查询时间的证据。支持生成工单草案，有权限的人员审阅并二次确认后，前端调用既有工单接口创建；Agent 本身不会修改数据库业务记录或执行硬件控制。

页面只提交最近五轮对话和当前页面名称，不会回传客户端的工具证据；后端每次重新读取数据库。对话和原始证据仅在浏览器内存保留，退出登录时清除。服务端审计保存工具名称、状态、耗时、草案数量和请求编号，不保存完整聊天或原始遥测。必要的工具结果会发给 DeepSeek，接入真实场地前应获得数据出境/外部服务使用授权并评估脱敏。

## 后端配置

在后端的未跟踪 `backend/.env` 中配置：

```dotenv
DEEPSEEK_API_KEY=在本地填入你的密钥
DEEPSEEK_MODEL=deepseek-flash
AI_ASSISTANT_RATE_LIMIT=20/hour
```

配置后重启 Django 服务。密钥只在后端使用；不要放进 `frontend/.env`、任何 `VITE_` 变量或浏览器代码。页面需要登录正式数据服务，演示登录模式不会调用付费接口。

容器部署时，在服务端环境提供同名变量；生产 Compose 仅向 `api` 容器传递密钥，网页构建和浏览器都不会接收它。

后端的 `POST /api/assistant/chat/` 要求可读取运维页面的 Bearer 登录凭据，采集服务账号不可调用。每次最多接收 12 条消息、每条最多 2000 字、总计最多 8000 字；只接受 `user` 和 `assistant` 角色，最后一条必须由用户发送。默认每名用户每小时最多请求 20 次。

请求处理最多 7 次模型调用、6 次工具调用；模型请求总时间预算 55 秒（单次网络超时至多 18 秒），前端超时 65 秒。发布整合版保留主线 ASGI/Daphne 容器与 WebSocket 路由，Nginx HTTP 上游读取超时为 75 秒；原本地 Gunicorn 方案不覆盖主线部署。另有云端负载均衡/代理时应核对其超时，避免中断工具循环。数据库查询耗时不具有硬实时保证。模型调用不自动重试，以免放大费用和重复业务意图。

工具参数在后端校验：只允许指定工具及字段，资产必须真实且启用，趋势窗口为 1–60 分钟。资产列表上限 80，告警/工单上限 15，快照每资产上限 20 项指标，趋势只统计最新 500 个样本、最多 30 个单位/质量分组，并明确截断范围。不允许任意 SQL、shell、文件、URL 和 MQTT 指令。

生成草案需要运维员/管理员权限，且同次请求已查询该资产快照与未完成工单。草案不创建记录；用户确认后使用现有工单权限和幂等键，失败重试复用同一键。草案阶段会再次拒绝该资产已有未完成工单或本次已有草案的情况；确认前后并发创建的其他工单仍应人工核查，通用创建接口不提供跨幂等键的语义去重。写入保留既有工单审计。

返回字段：`reply`、`queriedAt`、`mode`、`traces`、`evidence`、`proposals`、`locations`、`inspection`。`tool_verified` 只代表调用了工具，不代表大模型全部表述已被自动事实校验；每项证据应逐项核对。`explanation_only` 表示未成功调用任何工具，不可视作已查询现场。

数据新鲜度沿用平台心跳宽限设置（间隔乘系数与最小宽限取较大值）；无绑定/无心跳为未知，不擅自假设在线。返回采样/接入时间、质量、新鲜度和未来时间戳警示。不同单位与质量不混合统计，坏质量只计数，不计算平均值。数据库快照不是持续实时流，原始气体 ADC/电压不是标定浓度，项目内部手册不是现场批准的安全规程。

DeepSeek 接口地址固定为 `https://api.deepseek.com/chat/completions`，默认使用 `deepseek-flash` 非思考模式；如需更强的模型，可将 `DEEPSEEK_MODEL` 设为 `deepseek-v4-pro`。助手回复仅供参考，现场状态以设备、告警和工单页面的实际记录及人工核查为准。

## 验证与使用

后端回归：`python manage.py test operations.test_ai_assistant operations.test_ai_agent --noinput`。

前端：在 `frontend` 执行 `npm test`、`npm run build`。组件测试覆盖二次确认、只读角色、失败重试幂等；Store 测试覆盖证据不回放及退出后迟到响应丢弃。

建议先问“查询 CTRL-01 的最新采样和数据新鲜度”，打开“核查过程与证据”查看实际时间和值；再问“检查活动告警，检索排查手册，给相关资产生成处置工单草案，先核对已有工单”。如果工具预算不足，请缩小到单个资产分步提问。重启后端/重新构建运行前端后生效，不需要修改 STM32 固件。

本地模拟上游测试不等于真实 DeepSeek 模型效果验收，真实数据联调、外部访问、时延/费用、提示注入红队及现场安全审批仍需完成。


## 2026-10-25：四主控五检测点升级

新增 `station_snapshot`、`diagnose_station`、`review_work_order` 三个只读工具。31路身份清单与四份带来源、版本和SHA256的内部手册随后端镜像打包，路径为 `backend/operations/agent_catalog/`；运行时不依赖模型工程目录。每资产读取最多20项最新指标，整批巡检不按每个传感器逐个请求数据库。四控制器的身份/心跳与31个物理传感器分别列出。

登录后打开页面右下角助手，点击“五站31路巡检”，会直接调用 `GET /api/assistant/inspection/?station=all`。这个入口不调用DeepSeek，缺少模型密钥时仍可核对台账、测量和模型映射。P1～P5与all之外的检测点及额外参数会被拒绝。只读用户可巡检，采集账号不可读取。

助手显示按检测点汇总的巡检表与服务端生成的设备卡片。设备卡片只能跳转固定三维路由中的当前有效资产，不能把模型返回的任意URL或mesh当作定位。缺资产、空mesh、mesh不一致、激活模型未验证、节点缺失或重名会分别显示；不会自动创建、改名或绑定设备。

排障工具同时取本站、20个主要气体/火焰探测器、近5分钟同资产同指标同单位的原始变化、双风机与近10分钟控制审计。趋势每资产最多60个良好非演示样本；只提供原始量变化，不输出校准浓度或扩散预测。现有控制审计可能对应旧版CTRL-01双风机协议，必须与新四节点迁移区别看待。

`review_work_order`分别输出通信状态、工单更新后是否出现新的可用观测、活动告警和人工验收要求，不关闭记录。心跳、新样本和告警消失都不会单独被宣称为维修完成。

三维叶轮控制已接入 `TwinScene.vue`：采用V17 glTF局部轴，每台风机只使用自己的`rotational.speed`；读取配置的硬件采样周期并逐帧检查心跳/测量是否过期。缺失、未来时间、不良质量、非rpm、演示或离线反馈均冻结并显示未知。旧模型缺少独立叶轮也显示未知。视觉速度上限90rpm仅用于画面，界面保留反馈数值。切换模型和卸载组件会释放控制器。原正式GLB及V16/V17文件均未覆盖，启用新模型仍走现有管理员校验/发布流程。

命令行可执行 `python manage.py inspect_stations` 只读检查；`--station P5`缩小范围，`--output 新文件.json`写出报告，已有文件不覆盖；`--strict`遇到缺项、观测不可用或模型节点未验证时返回失败，不代表硬件验收。
