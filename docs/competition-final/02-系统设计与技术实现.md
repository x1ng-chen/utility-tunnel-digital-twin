# 系统设计与技术实现

系统采用现场控制与网页运维分层。STM32 负责就近采样，ESP32-S3 网关汇总帧，平台保存观测并计算业务状态，三维和 Agent 从同一套资产与观测接口取数。每段链路有自己的故障语义，便于区分探头、主控、总线、网关、平台和界面问题。

## 1. 台架和点位

V24 台架方案以约 700 × 700 × 300 mm 的透明展示箱为设计口径。五个检测站用 P1–P5 编号，四块 STM32F103RCT6 负责分区采样，以缩短区域内的传感器线束。主控之间的跨区链路为共享 RS-485 主干。统一编号在固件、资产台账和模型节点中核对，视图旋转时仍按资产编号识别。图见[项目总览](01-项目总览.md)。

| 主控 | 台账归属 | 登记 / 现场启用 | 关联实例 |
| --- | --- | --- | --- |
| CTRL-01 | P3、P5 | 11 / 11 | P5 火焰探头 `FLAME-05`，ENV-03 缺测排查 |
| CTRL-02 | P4 | 7 / 6 | `ENV-04` 停用，`FAN-02` |
| CTRL-03 | P2 | 6 / 6 | P2 分区采集 |
| CTRL-04 | P1 | 7 / 7 | P1 分区采集，`FAN-01` |
| 合计 | 5 站 | 31 / 30 | 保留停用项历史和三维身份 |

31 路按设备登记统计。MQ-2、MQ-4、MQ-7、火焰探头各 5 路，温湿度 4 路、液位 4 路、氧气 3 路。风机是独立执行资产，供电与反馈作为独立观测处理。P5 没有 SHT30，巡检需要区分“该站未配置”“已配置但缺测”和“已配置但观测过期”。这三个状态会导向不同的下一项检查。

### 通讯与上报

1. STM32 业务固件采集区域内模拟量、数字输入和 I²C 设备，维护寄存器与设备状态。火焰类短事件需要保留瞬时输入和锁存事件的区别。
2. 网关通过 RS-485/Modbus RTU 轮询四块主控，汇总控制器身份、帧或序号、传感器值和状态，并通过 MQTT 上报。网关使用独立 ESP32-S3，采集与通信任务运行在网关的 FreeRTOS 环境中，和小管语音板分别运行。
3. Django 接收归属已配置的资产数据，保存观测、时间、来源和质量，并按条件更新告警。新鲜度取决于实际观测时间，收到报文和观测可用于诊断是两层检查。
4. Vue 前端读取台账、趋势和告警，实时状态变化驱动三维节点。浏览器能定位到模型设备，也能返回告警详情和 Agent 任务记录。
5. Agent 获取服务端冻结的事件和观测。正常页面可以随数据刷新，旧任务应继续显示自己使用的来源、时间范围和快照散列。

### 现场输入与状态分层

| 信号 | 能说明的事 | 使用约束 |
| --- | --- | --- |
| 火焰 `0/1` 瞬时采样 | 某时刻探头输入状态 | 需查质量和时间。触发输入可由台架试验产生，判断真实火情还需要独立证据 |
| `latched_event` | 短事件曾被固件锁存并随帧上报 | 要结合事件类型、时间和质量，与实时采样分别解释 |
| SHT30 温湿度 | 温、湿原始测量转换后的环境数据 | 先核对启用状态、新鲜度和读取质量 |
| MQ／氧气原始 ADC | 趋势、阈值输入或板端原始观测 | 气体浓度和安全进入判定需要校准与适用规则 |
| 风机命令回执 | 指令被接收或处理 | 输出状态、端子电压、转速分别取证 |
| INA226 电参量 | 具体支路电压、电流等读数 | 设备连通与现场通停可作为阶段证据，精度与转速验收独立 |
| TACH / RPM | 质量良好时可支持转动判断 | 信号异常、陈旧或质量待核验时应保留未知 |

## 2. 用统一资产串起数据、三维与业务

以 `FLAME-05` 为例，固件／网关将该点归到 CTRL-01，平台关联 P5 资产，三维页通过节点绑定定位到探头，告警详情用该资产预选排障表单。排障任务还绑定具体告警 ID，避免把 P5 其他历史告警的读数带进来。关联工单保存来源告警和资产，恢复后的事件仍可追溯。

| 对象 | 核心字段 | 对应界面 |
| --- | --- | --- |
| 工位、设备与模型映射 | 工位、资产编号、控制器、启用标识、模型节点 | 运行总览、资产/三维详情 |
| 观测 | 资产、时间、采集与入库信息、数值、质量、来源 | 设备读数、历史趋势、任务取证 |
| 告警 | 编号、资产、触发和恢复时间、事件状态 | 告警列表/详情、三维高亮 |
| Agent 任务 | 目标、告警、来源、快照及散列、角色轨迹、复核结果 | Agent 工作台 |
| 工单 | 来源告警、关联资产、处理状态、人员动作和时间 | 工单详情与处置记录 |

V24 模型的透明壳、分区托板、主控、管线和风机用于建立空间对应。风机示意将旋转、RGB 灯光与控制状态分开表达。现场即使有供电或灯光亮起，也需核验转速或明确的人工观察才能判断实际转动。拓扑同样区分“配置上共用一块主控”和“测量已证实故障原因”。

## 3. 服务和权限

| 层 | 技术与职责 | 数据或权限边界 |
| --- | --- | --- |
| 边缘 | STM32 业务固件、RS-485、ESP32-S3 网关、MQTT | 现场配置决定启用点位，网关报文与控制回执可单独核对 |
| 数据与业务 | Django API、数据库、资产/观测/告警/工单、身份权限 | 现场数据、隔离模拟、历史回放分别标识。工单状态变更由业务接口记录 |
| 智能体 | 工作进程、DeepSeek 兼容接口、受控工具、版本化知识检索 | 工具依据角色、目标和来源授权。评审环境可运行只读任务 |
| 界面 | Vue、Three.js，工作台与三维/告警/工单互相定位 | 页面预选参数只填表，实际运行需要用户发起。最终权限由服务端检查 |
| 语音 | 小智固件、独立语音 ESP32-S3、语音服务、巡检接口 | 小管负责查询与播报。证据核查、动作确认和工单留痕走网页 |

权限上区分“运行只读 Agent”“浏览业务记录”和“修改业务状态”。评审账号的三项演示可以在自己的任务范围内执行，工单和实物控制写入仍需在对应环境按权限受控。典型告警、网页验收与真实模型记录均需保留来源。

## 4. 小管的现场使用和降级路径

小管终端负责唤醒、麦克风采集、屏幕状态与语音播放。明确的站点巡检走巡检接口 `/api/assistant/inspection/`，语音服务用查看者身份取数，并播报站点、数据状态和需要提示的缺项。开放式回答走配置的对话模型。明确查询和开放回答的依赖可以分别诊断。

联调先验证唤醒后进入聆听、OLED 上报音量和播放状态，再排查无声、后端模型提示及播放延迟。后续实物阶段用户听到了 P5 的正常播报。完整端到端延迟、断网重连及并发无同口径统计。比赛中保留“小管查 P5”短镜头，随后在网页展示同一站点及数据时间。

## 5. 硬件和运行限制

- `ENV-04` 停用保留资产身份、历史、寄存器和三维绑定。`ENV-03` 温湿度曾缺测或过期，应留作台架复测项。
- 11 月 3 日在 30 分钟监测中记录到 CTRL-04 一次新帧间隔超 15 秒，长稳门槛未通过。一次现场演示和连续运行可靠性分别统计。
- K210 的摄像头和板载 LCD 已能实时预览，水平/竖直方向经实际文字确认。P5 观察框也完成对准。视觉误报和烟雾识别仍缺验收，主线使用实体火焰探头。
- 项目是缩比原型。现场化需继续补齐工业传感器、校准、链路可靠性、权限和经批准的安全规程。
