# 比赛材料与评审演示

作品可用“发现短告警后，如何找到证据并完成一次可信复核”解释产业问题。评委能看到实物与三维，亲自发起运维任务，并点击每条结果对应的证据。示范围绕 P5 的同一条历史实测告警 `1234` 展开。

## 1. 规则与作品的对应

以 2026 年 11 月 10 日 24:00（北京时间）为校赛官网报名及作品上传节点。提交时同时核对本校组织通知是否提前收件。比赛主题为智能体在真实产业场景中的应用，实际操作与可复核结果是材料重点。 [大赛官网](https://www.ai-race.com.cn/) · [高校赛事通知](https://gkgc.sdufe.edu.cn/info/1099/17650.htm)

| 随队提交说明中的材料 | 限制或做法 | 本作品可使用的内容 |
| --- | --- | --- |
| PPT | 16:9、最多 20 页、50 MB 以内。至少展示三条提示词及结果 | 项目全貌、P5 任务、三角色执行、规则与资料、真实验收、公开入口 |
| 视频 | MP4、不超过 6 分钟、300 MB 以内 | 同一条告警贯穿实物、三维、Agent 和人员处理，配第二轮归档证据 |
| 可操作智能体 | 评审链接和专用测试账号/密码 | 独立历史实测回放，账号可跑只读任务并查结果 |
| 命名与匿名 | PPT、视频按“命题领域-学校-队长姓名-作品名称”命名，作品内容匿名 | 画面、网页、口播、文件内信息和账号显示名脱敏，文件名按正式系统要求填写 |

页数、时长和匿名细则来自队内收到的《提交说明.pdf》。正式上传前以当前系统页面为准。本文提供文字和验收口径，供制作材料时选取。

## 2. 评委真正可以操作的三个任务

归档的 P5 结果用于说明证据和校对新运行。评分验收应以评审地址登录后实际返回的结果为准。同一快照上模型可能换措辞或得出保守结论，检查重点是范围、引用、质量和权限。

| 顺序 | 入口与设置 | 可复制的提示词 | 应看到的结果和证据 |
| --- | --- | --- | --- |
| 1 · 巡检 | 登录 → 智能体运维中心／Agent 工作台 → 巡检 → P5 → 运行 | 巡检 P5。按该站资产列出可用、过期、缺测和未配置项，写明数据来源与时间。 | 结果写明 P5 及“历史实测回放”，给观测时间和质量。P5 未配置温湿度。显示新鲜度口径，历史记录不可当现场实时 |
| 2 · 证据排障 | 告警 → 找到 P5 的 FLAME-05（现场编号 1234，回放按编码 ALM-AUTO-261106-D353FC 查找） → Agent 排障 → 三 Agent → 运行 | 复盘当前选中的 P5 火焰告警。分别列出触发、恢复的观测时间和证据，区分瞬时采样、锁存与后续快照。给出一项下一步检查。 | 运行卡显示正确资产、告警、来源和窗口。展开历史 `0 → 1 → 0`。分别查看取证、诊断、复核，以及人员与模型证据边界 |
| 3 · 工单复核 | 从告警查看关联工单 → 恢复复核／工作台输入工单编号 → 运行 | 复核本告警关联工单。哪些信息是现场观察，哪些来自模型？还有哪些核查没做？ | 显示来源告警编码、工单 `WO-261106-86E0D9`、关联资产和已有人工记录。工单已完成，仍能看到原模型 `revise` 和未进入冻结证据的项 |

任务 2 的归档真实结果包含三角色、六次模型调用，最终需修改。任务 3 的既有工单轨迹已记录创建、分派、处理、复核和完成。**三条提示词与实际可见结果的正式截图应在独立评审地址验收后保存。** [实物证据与归档详情](03-P5实物验收与证据.md)

## 3. 5 分 30 秒讲清一条事件

| 时段 | 画面和实际动作 | 讲述重点 |
| --- | --- | --- |
| 00:00–00:35 | 实体全景 → 近拍 P5 探头 → 切到三维全景 | 五站四主控。短告警结束后，当前读数可能已经变回正常 |
| 00:35–01:15 | 对小管说“巡检 P5”，网页对照 P5 站点、读数与时间 | 语音与网页使用同一平台数据，语音适合现场只读巡检 |
| 01:15–02:05 | 11 月 6 日现场记录或同条件另录：探头变化 → 三维高亮 → 恢复 → 打开告警 | 强调编号 `FLAME-05`。若使用既有归档，保留 1234 及对应时间。另录的新告警单独标记 |
| 02:05–03:30 | 告警详情进 Agent 工作台，显示选择范围、运行方式，展开三个角色和真实证据 | E1 的 `0 → 1 → 0`，锁存和当前读数区别，为什么不把坏质量当证据 |
| 03:30–04:25 | 打开复核意见，切换到报文对照和工单处置记录 | 模型没核到三维/报文，人员补记外部对照。解释 38 条的匹配字段和证据范围 |
| 04:25–05:05 | 查看人员分派与复核完成，再打开评审模式 | 人工完成业务，模型仍有缺项。评委使用历史实测回放来操作 |
| 05:05–05:30 | 小结、进入任务页面 | 用清晰的入口、来源和证据复述参赛价值，保留提示词展示 |

演示涉及多个时段时，使用事件编号和画面标签标明“实物录制”“历史实测回放”“隔离模拟”。若剪掉模型等待时间，用“等待已剪辑”说明。P5 的主线用火焰探头和现场记录，K210 可留在后续研发部分。

## 5. 上线验收口径

- 部署环境使用独立数据库和脱敏历史实测样例。页面明显标明回放来源。模型配置留在服务器，评审账号为独立查看者。
- 使用手机流量和另一条外网打开最终 HTTPS 入口。分别验证登录、三维加载、历史告警检索和三条只读任务实际运行。逐条保存任务 ID、结果状态、快照来源和运行记录。
- 验证评审账号尝试控制实物或修改工单时由服务端拒绝，并保留失败证明。视频中的人工结单来自实物验收档案，评审账号查看其历史。
- 模型若发生超时或 503，页面提示本轮运行结果及可重试状态。保留可打开的真实归档，实时运行验收仍须复测。
- 清理账号显示名、个人信息、桌面、浏览器头像、通知、路径、终端输出和模型密钥。将评审登录凭证通过指定提交渠道提供。

交付状态以实际地址验收为准。当前这组 Markdown 汇集叙述、案例和验收口径，正式链接及登录状态应在提交前登记。

## 6. 评委追问时的简明回答

| 可能的问题 | 以什么作答 |
| --- | --- |
| 为什么用 Agent | 让评委打开工具轨迹。模型按任务调用数据、版本化知识和拓扑，取证和复核的输出能在同一告警核对 |
| 为什么三角色 | 展示具体的错误或缺项如何被拦截，如何退回补查。单 Agent 已能完成部分相同判断，对照材料保留运行差异 |
| P5 确实着火了吗 | 现场台架使火焰探头触发，确认的是探头输入、告警和三维链路。实际火情结论要靠合适的现场证据 |
| 为什么结单后模型仍显示需修改 | 工单复核使用了人员另行取得的材料，旧模型任务保留了当时的证据范围和判断 |
| 能否直接上生产 | 已有缩比台架和真实链路验收。生产还需要传感器校准、工业安全与链路长稳验证、现场审批和响应流程 |
