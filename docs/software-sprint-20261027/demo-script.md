# 现场软件演示与人工评分脚本

1. 管理员登录智能运维；确认“模拟测试”及旧模型主控文字提示可见。选择INS-01重置，开始采样，先展示五站31路清单与布局身份。
2. 点击五站巡检后提交模型任务，展示实际调用、证据编号和五站定位卡片。简单巡检只有取证Agent是预期行为。
3. 推进到阶段1，P5原始量变为450 adc并触发现有规则。选择证据排障与P5，说明只有原始量，不能说达到危险ppm。
4. 展示三个实际模型输出、原始测量及规程检索片段。复核若拒绝/证据不足，展示原因而不继续执行；不要跳过失败。
5. 工单草案任务明确填MQ4-05，先点审阅再取消，确认工单数未增加。再次生成后人工确认，记录真实测试编号；重复提交仍是一条。
6. 若要演示动作，任务中明确要求为FAN-01提出仿真PWM建议。复核通过后审阅、确认，查看命令UUID/CTRL-04/模拟回执。回执不会清除P5告警。
7. 推进到阶段3，等新采样和规则恢复；输入明确工单号进行恢复复核，工单不自动完成。重新核查展示新旧快照差异。
8. 暂停采样并等待60秒以上，展示数据自然过期；恢复采样后显示新时间。结束暂停，防止长期积累无用演示数据。
9. 展示成本面板，调整两风机假设功率和电价；指出仅两支路、模拟估算、非实测收益。

## 人工组与评分约束

使用同批导出的 `*-packet.json`：人工组、普通问答组和Agent组有相同任务与原始信息。不给人工组预设答案、Agent结论或规程推导。记录开始、结束及每项操作，不把模型等待时间从Agent组剔除。

逐项填写 `human-scoring.csv`。检查31路覆盖、身份、数据质量/时效、候选原因与反证、引用存在及适用性、动作权限和工单行为。分开记录任务完成、结构化校验、人工事实判断与耗时；不知道填未知，不能以“复核pass”替代事实正确。

12复合场景使用配对结果。单Agent/三Agent的首次失败保留，修订后重测单独记批次；不得只选成功案例或以调用次数证明效果更好。
