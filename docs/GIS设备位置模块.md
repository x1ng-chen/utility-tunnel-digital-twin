# GIS 设备位置模块

## 职责边界

GIS 总览使用 WGS84 经纬度显示开发板实物模块的地理位置与接入状态；“设备台账”负责运行检索和导出，“资产主数据”负责管理员维护设备身份、内部二维坐标与 WGS84 坐标。三个模块共享同一 `Asset` 数据，不重复维护业务状态。

## 坐标真实性

未配置坐标的普通资产使用 `unassigned`；当前种子数据使用 `demo_anchor` 坐标源，仅用于验证 GIS 交互，页面会持续显示“非 GPS/非现场测绘”提示。正式现场坐标必须使用以下来源之一：

- `configured`：经审批的人工配置；
- `surveyed`：现场测绘；

本项目当前不把 GPS 设备采集结果直接写入系统；如未来引入定位设备，应先将其接入链路转换为受控的 `surveyed` 或 `configured` 空间成果，并保留来源编号、采集时间和复核记录。

数据库约束要求经纬度同时存在，纬度范围为 `[-90, 90]`，经度范围为 `[-180, 180]`。接口用数值返回坐标，前端再次验证有限数和 WGS84 范围后才创建标记。

## 底图配置

前端使用项目内锁定的 Leaflet 1.9.4，不依赖浏览器 CDN 脚本。开发环境可使用 OpenStreetMap 公共瓦片并保留署名；其公开服务没有生产服务等级承诺，生产环境必须按组织网络与供应商条款配置获批或自建瓦片服务：

```dotenv
VITE_GIS_TILE_URL=https://tile-provider.example.com/{z}/{x}/{y}.png
VITE_GIS_ATTRIBUTION=Map data attribution required by provider
```

底图加载失败时，页面进入“降级”状态，资产数据、筛选和详情仍可使用。生产容量、缓存和服务等级不依赖 OpenStreetMap 公共开发瓦片。

## 受控空间数据与发布流程

真实 GIS 图层不再由浏览器种子坐标伪造，而是由 PostgreSQL 中的 `SpatialFeature` 管理。每个对象有唯一编码、图层类型、WGS84 GeoJSON、来源、来源编号、精度、采集/复核时间、状态和乐观锁版本。支持的图层为管廊段、检查井、阀门/人孔、巡检路线、风险区域和安装点。

1. 管理员在“空间数据管理”导入 1–100 条 GeoJSON FeatureCollection；接口仅接受 Point、LineString、Polygon 与 `EPSG:4326`，拒绝越界、非有限数和未闭合面环。
2. 导入对象默认作为 `draft` 草稿；录入测绘或 CAD 成果编号、精度与必要说明。
3. 管理员完成复核后，以版本号提交 `published`；服务端要求 `verifiedAt` 和非空 `sourceReference`，同时写入审计记录。
4. 运维 GIS 只展示 `published` 对象；管理员可查询草稿和退役对象。`bbox` 查询采用对象包络相交，确保跨越视口的线/面不会被遗漏；它不是替代 PostGIS 的精确空间拓扑运算。

## 硬件位置与通信接口的边界

`HardwareBinding` 是资产与未来真实通信端点之间的一对一受控契约，记录协议、设备标识、主题/端点、期望心跳、状态和版本。种子环境为每个已盘点实物资产创建 `reserved`（接口已预留）契约；这不等于设备已经联网，也不会产生在线心跳或遥测。

- 空间对象用于表达真实管廊、井位、巡检路线和风险区域；资产安装点仍归资产主数据管理。
- 只有网关接入服务完成认证、校验并写入真实心跳后，绑定状态才可更新为 `connected`。
- 硬件实物尚未完成时，系统保留接口与审计边界，不把模拟数据写成现场事实。

## 数据模型与筛选

`Asset` 包含 `hardwareCode`、`integrationStatus`、`interface`、`capabilities`、`latitude`、`longitude`、`locationSource`、`installationNote`、`isActive` 和 `version`。`GET /api/assets/` 支持 `integrationStatus`、`hardwareCode`、`hasLocation=true|false` 与生命周期筛选，并保留原有搜索、状态、区域与分页参数。

管理员通过独立的“资产主数据”页面修改位置。服务端强制经纬度成对、WGS84 范围、坐标来源一致性以及平面 `x/y` 的 `0–100` 范围；更新必须携带版本号。已有活动告警或未结束工单时禁止停用资产，避免 GIS 标记消失后留下无法处置的业务记录。
