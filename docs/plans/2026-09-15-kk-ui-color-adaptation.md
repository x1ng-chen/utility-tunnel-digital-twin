# KK_UI 彩屏适配实施计划

**目标：** 在不破坏现有双节点、摇杆、风机控制和 ST7735 硬件 SPI/DMA 的前提下，吸收 KK_OLED/KK_UI 的静态页面、事件分层和非线性动画设计，形成适用于 128x128 RGB565 彩屏的系统菜单。

**适配原则：** 原版 KK_OLED/KK_UI 仅支持 1-bit 单色页式显存，因此不把其运行时直接加入固件。项目保留现有 ST7735 驱动和局部刷新，以项目拥有的彩屏适配模块复用 KK_UI 的 MIT 许可动画算法和静态页面模型。Node B 继续拥有交互与命令下发，Node A 保持只读状态屏。

## 阶段 1：工程级 Skills

- 将 `kk-oled-use`、`kk-oled-font`、`kk-oled-port`、`kk-ui-use`、`kk-ui-port`、`kk-ui-extend` 完整复制到 `.agents/skills/`。
- 保存 KK_OLED 和 KK_UI 的 MIT 许可证。
- 确认运行时资产未被 CMake 直接编译。

## 阶段 2：彩屏动画适配（TDD）

**文件：**
- 新增 `Core/Inc/kk_ui_motion.h`
- 新增 `Core/Src/kk_ui_motion.c`
- 修改 `tests/ui_renderer_host_test.c`
- 修改 `Core/Src/ui_renderer.c`
- 修改 `CMakeLists.txt` 与主机测试脚本

1. 先把现有线性动画测试改成 KK_UI 非线性缓动期望，并运行确认因缺少新行为而失败。
2. 移植固定点 Q12 缓动与插值，不使用浮点和动态内存。
3. 让页面滑入和选中条动画统一使用该模块。
4. 运行 UI 渲染主机测试并检查时间回绕边界。

## 阶段 3：静态页面模型（TDD）

**文件：**
- 新增 `Core/Inc/kk_ui_catalog.h`
- 新增 `Core/Src/kk_ui_catalog.c`
- 新增 `tests/kk_ui_catalog_host_test.c`
- 修改 `Core/Src/ui_state.c`
- 修改 `Core/Src/ui_renderer.c`

1. 先写页面路由、行数、标题、首页入口和可编辑项类型的行为测试，并确认失败。
2. 建立静态页面目录：安全总览、分类监测、报警中心、风机控制、灯带与蜂鸣器、通信状态、系统设置。
3. 状态机与渲染器共用同一目录，消除重复的行数和路由表。
4. 保留现有 `UiEffect` 命令边界，控制指令仍由应用层发送，UI 不直接操作硬件。

## 阶段 4：页面和交互验收

- 首页：摇杆上下选入口，确定进入，左移或长按返回。
- 分类监测：环境、气体、积水火情、风机供电均显示实时值与数据质量。
- 风机控制：风机 1/2 支持 0、30、60、100%，危险操作保留确认与执行反馈。
- 灯带/蜂鸣器：模式、亮度、测试/静音/恢复保持现有命令协议。
- 顶部状态：实时时间、控制器编号和链路状态。
- 页面切换、选中条和数值编辑采用允许跳帧的非线性动画；不建立帧队列。

## 阶段 5：双节点构建验证

1. 运行全部显示、状态机、摇杆和命令主机测试。
2. 分别构建 `node_a` 与 `node_b`，记录 Flash/RAM 变化。
3. 检查两个固件均生成最新 `.bin`，但未收到明确烧录指令前不自动写入设备。
4. 实物验证留给烧录后：文字、边缘、动画流畅度、摇杆操作、实时数据和风机命令回执。
