# 前端布局与交互优化（2026-10-29）

## 设计依据与方向

使用GitHub上游的两项技能指导本轮工作：

- [Impeccable](https://github.com/pbakaus/impeccable/tree/main/.agents/skills/impeccable)，本机安装版本4.8.0；读取layout、audit、operate与craft-floor规范。
- [Anthropic frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)。

保留现有浅色工业运维界面，面向值守人员完成查看、定位、排查和复核任务。三维场景与实际任务结果是主要内容；导航、来源提示、辅助工具是支持内容。没有增加宣传性指标或把模拟数据作为现场证据。

基准配色：页面背景`#f2f6fb`、内容`#ffffff`、文字`#1c3049`、辅助文字`#53657b`、操作蓝`#1766c3`、告警红`#b9364d`。保留原有成功和警示语义色。采用系统中文无衬线字体，操作页正文与控件以13～14px为主，标题28px、手机24px；4/8/12/16/24/32px为主要间距。

Impeccable上下文启动器首次下载未完成，已停止；本轮直接读取现有代码与项目历史上下文。没有取得其机械检测器报告，不以此声称自动检查全部通过。

## 主要问题与处理

| 原问题 | 处理 |
| --- | --- |
| 手机导航只剩拥挤图标，入口难辨 | 改为完整文字抽屉；支持遮罩、Escape、焦点循环/返回、背景inert和滚动锁 |
| 导航序号和路由进度条形似任务进度 | 移除装饰性序号与进度，保留真实菜单名称与告警数量 |
| 顶栏状态、时钟和搜索挤在一行 | 支持中等与窄屏换行，保持服务与推送状态可辨 |
| 标题过大、多个小字号及页面留白不一致 | 缩减标题、统一共享控件、表单、表格字号与键盘焦点 |
| 风险列表、选中状态和切换栏覆盖模型 | 普通视图移到场景外，风险列表可展开；设备详情在中等宽度放到模型下方 |
| 初次打开三维页自动放大历史告警设备 | 默认全景；明确资产链接、用户选择或新告警仍可以定位 |
| 工作台各工具与结果同等权重，长记录难查 | 区分任务输入与实际结果，辅助知识/经验/成本折叠，长轨迹局部滚动 |
| 服务端暂停模型调用，按钮仍可点击 | 读取服务端暂停标志并显示原因；保留历史与只读工具 |
| 手机遥测记录被旧规则强制撑到820px | 重置卡片行最小宽度，保留各字段标签 |
| 设备示意图在手机堆满密集节点 | 窄屏使用既有设备列表，明确说明，保留三维和地图入口 |
| 实物只读环境的控制禁用原因被误写为账号问题 | 按服务端配置、网络和角色分别显示原因，不改变控制权限 |
| 恢复API会话时短暂出现旧演示设备/告警 | API会话先显示空的待加载状态；切换来源清除模拟记录；后续API失败保留真实历史快照 |

另修复告警筛选选中语义、工单新建面板展开状态、配置页窄屏网格、审计长文本及分页布局。保留既有硬件控制禁用、人工确认、来源质量和历史记录规则。

- 最终前端功能回归：143项通过、1项既有跳过，涵盖导航、数据来源切换、模型暂停、工单确认和定位行为。

- 浏览器实际查看1280×720桌面及390×844窄屏；检查了工作台、导航抽屉、遥测记录、设备台账、配置页和调整中的三维页。

- 没有付费模型调用，没有下发硬件命令，没有修改或重建模型文件。本轮没有推送GitHub。
