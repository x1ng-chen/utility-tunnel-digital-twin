# 面向参赛的Agent任务主线

2026-10-29。在前一轮布局与可用性优化之上，根据用户指出“没有突出Agent功能”，补充任务与执行证据的主线。本轮不是新的Agent算法，也不是最终真实模型验收。

## 要求与判断

大赛官网`https://www.ai-race.com.cn/`为动态页面，本轮网页检索未取得其详细评分规则正文。核对[山东财经大学2026-10-23赛事通知](https://gkgc.sdufe.edu.cn/info/1099/17650.htm)及[电子科技大学转载通知](https://www.mba.uestc.edu.cn/info/1013/8471.htm)：强调真实业务场景、可验证智能体交互、问题解决和应用价值。未据此发明评分比例或“必须三Agent”的硬性要求。

项目侧判断：监控指标、三维场景和聊天入口不能单独说明Agent如何解决运维问题。应能从具体任务进入，并看到实际工具调用、证据、候选原因、复核退回及人工确认；三维定位为任务服务。效果与收益仍需实际评测证明。

## 本轮实现

- 首页标题改为“智能体运维中心”，在监控指标前提供五站巡检、当前告警排障、待复核工单入口；三角色职责说明明确标注为说明，不冒充运行结果。
- Agent工作台置于主要导航首位；保留运行总览、三维、告警和数据等入口。
- 告警行增加“Agent排障”，把实际资产、告警和工位准备到任务表单。未绑定工位使用全部范围，提示词要求先核对归属，后台仍校验现行台账。
- URL只接受白名单任务、工位及有限标识，不接受提示词载荷、重复参数或自动启动标志；查看者不能通过链接预选运维员专用草案任务。
- 点击入口不产生模型请求、命令、工单或审批；用户明确开始后才调用既有任务API。服务端暂停模型调用的限制保留。
- 执行记录按实际`steps`展示：角色、阶段输出、模型请求数、工具名称、返回/拒绝状态、查询时间和证据编号；完整参数和返回值可展开。
- 展示结构化候选原因、缺失信息、下一项检查及复核意见。未运行角色不渲染，缺输出不标记成功，允许出现退回修改和中断。
- 结果显示该任务冻结的目标、来源和快照散列，不能用当前页面来源替代旧任务来源。
