# FLAME-05 台架报警验证（2026-09-27）

## 实物链路

- Node B 的 FLAME-05 映射到 PC7；输入按低电平有效采样，CTRL-02 经本地 MQTT `ut/v1/CTRL-02/telemetry` 上报 `flame.alarm`。
- 用户用打火机靠近探头时，模块指示灯亮。后端 SQLite 收到 FLAME-05 的 `good` 品质读数：未触发为 0，持续触发时连续为 1。
- 后端阈值 `flame.alarm`（预警 0.5、严重 0.9）生成两条严重告警：`ALM-AUTO-260927-258583` 于本机时间（UTC+9）21:57:26 开启、21:57:30 自动恢复；`ALM-AUTO-260927-16CC90` 于 22:01:35 开启、22:01:49 自动恢复。后一轮活动约 14 秒，解除后 FLAME-05 恢复为 0。没有留存活动告警。

## 三维显示

- 网页运行时 GLB 的 SHA-256 为 `a89b5d09ea26c5db5c17acb72ac920fd9dd37697e009525fa0d81fc442dc8dab`，与 `model/README.md` 记载的用户 V13 导出相同；其节点包含 `FLAME-05-板`。

## 本轮修复与限制

- 网关现同时订阅 CTRL-01、CTRL-02 遥测，并为两个来源生成不同的事件 ID。
- 后端当前仍缺少部分其他传感器资产。网关在整批因未登记资产被拒绝时，将未登记读数送入持久死信队列，保留并重试已登记读数；因此 FLAME-05 可独立入库。本轮网关测试 28/28 通过。
- 上述资产与阈值登记在本机运行数据库；其他实物传感器的资产台账仍需另行完善。本次只验证 FLAME-05 报警链路。
