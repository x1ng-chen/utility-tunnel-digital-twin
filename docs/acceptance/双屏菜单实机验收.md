### 3.8 命令主题（用于联调核对）

| 角色 | 订阅 | 发布 |
|---|---|---|
| ESP-01（`CTRL-01`） | `ut/v1/CTRL-01/cmd/#`（含 `cmd/menu`） | `ut/v1/CTRL-01/telemetry`、`ut/v1/CTRL-01/cmd_ack`、`ut/v1/CTRL-01/status` |
| ESP-02（`CTRL-02`） | `ut/v1/CTRL-01/telemetry`、`ut/v1/CTRL-01/cmd_ack` | `ut/v1/CTRL-01/cmd/menu`（**唯一**串口发布主题）、`ut/v1/CTRL-02/status`（在线状态 / 离线遗嘱） |

> ESP-02 的发布分为两条独立路径。**串口帧**：`firmware/esp8266-01s/src/screen_routing.cpp`
> 为 `CTRL-02` 只定义了一个串口发布主题 `ut/v1/CTRL-01/cmd/menu`，`main.cpp` 对
> 每一个待发帧都返回该主题，这是**唯一**的串口发布路由。**状态主题**：`main.cpp`
> 的公共 MQTT 连接路径用 `BUILD_DEVICE_ID`（`platformio.ini` 中为 `CTRL-02`）构造
> `ut/v1/CTRL-02/status`，连接成功后发布 `online` 保留消息，并把 `offline` 配置为
> 遗嘱（LWT）；因此 `ut/v1/CTRL-02/status` 是**已实现**的 ESP-02 发布主题。
> 除该状态主题外，ESP-02 **没有** `ut/v1/CTRL-02/*` 遥测/状态发布通道：
> `ut/v1/CTRL-02/telemetry` 等主题目前**未实现**，不得作为联调核对依据。

菜单命令链路：`Node B STM32 → USART2 → ESP-02 → ut/v1/CTRL-01/cmd/menu →
ESP-01 → 归一化为 ut.command.v1 → USART2 → Node A → 执行 → ut.command.ack.v1 → 原路返回`。

## 5. 安全与凭据约束

- 两块 STM32 与两块 ESP8266 **都不保存华为云设备密钥**，也不直接连接 IoTDA；
  云端凭据只在网关侧通过环境变量注入。
- Wi-Fi 口令、MQTT 用户名/口令只写入 `firmware/esp8266-01s/include/secrets.h`
  （已 gitignore），**不得进入仓库、串口日志或本文档**。
- 本文件所有"回执样例"必须脱敏：只保留 `cmdId`、`status`、`reason`、
  `appliedValue` 与时间戳，不附带任何认证材料。
- 台架链路只允许在隔离局域网内使用明文 MQTT；不得把匿名 Broker 暴露到公网。
- 气体报警只在隔离信号模拟盒上注入；**不在教室释放可燃或有毒气体**。
