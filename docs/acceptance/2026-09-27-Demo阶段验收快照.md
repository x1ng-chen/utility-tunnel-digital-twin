## 本次 FLAME-01 修复

FLAME-01 模块检测指示灯在触发时亮，但旧 Node A 固件的轮转遥测多次上报 `flame.alarm=0`，三维页没有 FLAME-01 活动告警。代码检查发现：50 ms 的本地火焰采样会锁存报警约 12 秒，遥测却优先采用较慢的传感器库存读数，可能漏掉短触发。

Node A 已改为在首次检出 PB14 低电平时立即排队发送带连续序号的 FLAME-01 告警帧；队列满时重试。轮转帧在本地锁存期间也使用该报警状态。遥测主机测试通过；ARM 固件构建成功，大小 76,444 B，SHA-256 `0DAD18EC0517C16E8F4528BF890E3F9B439FF18072B604EAD21A15F4DAF651DE`。COM5 芯片 UID `FF33-05DA-3435484E-43038834` 与历史 Node A 一致；写入后独立回读 SHA-256 完全相同。用户将 BOOT0 恢复为 0 后，COM5 串口继续输出新固件遥测。

**待复测**：烧录后的现场检查时 CTRL-01/02 在 MQTT 保留状态中均为离线，尚未再次完成“FLAME-01 实物触发 → 后端告警 → V13 模型高亮”的全链路截图。指示灯亮和固件回读成功不能替代这一项实测。
