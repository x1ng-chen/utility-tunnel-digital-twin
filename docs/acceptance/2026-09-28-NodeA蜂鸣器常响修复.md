# Node A 蜂鸣器常响修复（2026-09-28）

## 现场现象与定位

现场蜂鸣器持续鸣响，Node A PB0 对 GND 实测约 3.3 V；同期后端 `CTRL-01/buzzer.active=0`，烟雾、火焰和甲烷报警遥测均为 0。代码检查发现，多传感器库中的报警可直接将 PB0 置高，却没有同步 `g_actuator.buzzer_on`。报警解除后，旧逻辑只有在 `buzzer_on=1` 且计时到期时才调用静音，因而可能将 GPIO 留在高电平。

## 修复与验证

- Node A 主循环在库报警生效时调用 `Buzzer_Start`，使执行状态与引脚一致；解除后对持续报警的无限期蜂鸣执行 `Buzzer_Silence`，并在无活动报警且状态为关闭时将 PB0 拉低。
- `cmake --build --preset NodeA` 成功：FLASH 76,484 B，RAM 14,320 B。
- 烧录前通过 COM5 识别 Node A UID `FF33-05DA-3435484E-43038834`；整片 256 KiB 备份保存在本地 `artifacts/flash-backups/2026-09-28/node-a-before-buzzer-fix.bin`，SHA-256 `5FF9174290A87CD424F3EA79D92AD9E4F89A0F115E03428B261CFEFF8A84FAAA`。备份文件含设备固件，未纳入 Git。
- 新映像 `firmware/stm32f103rct6/build/NodeA/stm32_controller.bin` 的 SHA-256 为 `99E0B1AA8C35C888135F0434C322EEEFE42A877176EF0DA4E8A1B304B0ED39F0`；COM5 写入后 `stm32loader` 返回 `Verification OK`，独立读取 76,484 B 后 SHA-256 完全一致。
- 用户将 BOOT0 恢复 0 并复位后，确认蜂鸣器已静音、PB0 对 GND 为 0 V。报警再触发与解除的完整实物回归尚未执行。

复测时 MQTT 保留状态显示 CTRL-01、CTRL-02 离线；这不影响上述本地 PB0 静音验证，但网络遥测恢复还需另行确认。
