# 实时遥测接入说明

## 数据链路

`STM32 → ESP8266 → Mosquitto → Fastify API → PostgreSQL → SSE → React 前端`

API 只订阅本地 Broker 的 `ut/v1/+/telemetry`。每个有效报文先写入 `telemetry_reading`，再通过认证后的 SSE 连接立即推送给前端；前端每 10 秒的 API 回读仅用于断流后的状态校正。

## MQTT 配置

在 `services/api/.env` 配置本地 Broker：

```dotenv
MQTT_URL=mqtt://127.0.0.1:1883
MQTT_TELEMETRY_TOPIC=ut/v1/+/telemetry
# MQTT_USERNAME=...
# MQTT_PASSWORD=...
```

启动 API 后，它会订阅 `ut/v1/+/telemetry`。不要把 MQTT 密码、数据库地址或云端凭据提交到仓库。

## STM32 上报报文

主题固定为 `ut/v1/ctrl-01/telemetry`；`assetCode` 必须已存在于平台资产台账，时间使用带时区的 ISO 8601。

```json
{
  "schema": "ut.telemetry.v1",
  "ts": "2026-08-27T10:30:00.000+09:00",
  "readings": [
    { "assetCode": "ENV-01", "metric": "temperature", "value": 25.4, "unit": "degC", "quality": "good" },
    { "assetCode": "ENV-01", "metric": "humidity", "value": 61.0, "unit": "%RH", "quality": "good" },
    { "assetCode": "SEEP-W01", "metric": "water.raw", "value": 1024, "unit": "adc", "quality": "good" },
    { "assetCode": "CTRL-01", "metric": "vibration.alarm", "value": 0, "unit": "bool", "quality": "good" }
  ]
}
```

当前 STM32 台架中的 DHT11、水位 ADC、SW-420 可按上述四个测点先接入；后续 SHT30、风机和气体模块沿用同一数组格式，不要新增私有 JSON 格式。

## 本地验证

在 API 使用的数据源中先运行迁移与种子，然后登录前端并选择 `API` 数据源。可用以下命令模拟一帧真机报文：

```powershell
mosquitto_pub -h 127.0.0.1 -t ut/v1/ctrl-01/telemetry -m '{"schema":"ut.telemetry.v1","ts":"2026-08-27T10:30:00.000+09:00","readings":[{"assetCode":"ENV-01","metric":"temperature","value":25.4,"unit":"degC","quality":"good"}]}'
```

前端顶部选择 API 数据源并成功登录后，环境读数无需刷新页面即可更新。未知资产编码、非数值数据、错误主题或不符合结构的报文会被 API 拒绝并记录错误，不会写入数据库。
