# 可信遥测接入说明

> 2026-09-28：当前功能分支双 ESP 的真实遥测已接入 Django，31 路传感器链路复测由项目方确认；L05 已拆除，气体仍使用原始量/电压。[PR #29](https://github.com/x1ng-chen/utility-tunnel-digital-twin/pull/29)还包含伪数值拒绝、默认 suspect、仅 good 样本参与聚合及设备回执校验，未合并状态见 [版本索引](项目当前状态.md)，不能假设所有分支都有这些改动。

## 当前软件链路

平台侧主链路为 `软件数据源 → Django REST API → PostgreSQL → 阈值规则 → 告警/资产/审计 → Vue 3`。真实台架数据经 IoTDA 网关转发后，同样只通过 `POST /api/telemetry/` 批量写入（见下文“双路输出”），不绕过 API、不直接访问数据库。

遥测通过 `POST /api/telemetry/` 批量写入。2026-09-10 起，Django 单进程 ASGI 可将已提交的遥测、告警、资产和工单变更下行推送至已认证浏览器：连接先完成首帧认证，再按 epoch/seq 重放或明确要求 REST 补读。前端显示“实时推送已连接／连接中／断开补读”，不会把数据服务在线误称为现场设备在线。

浏览器仍会在实时流断开时进行有限 REST 补读；这不是把 2 秒轮询伪装成推送。当前进程内事件缓冲不支持多 API 副本或独立 monitor 进程的完整跨进程推送，相关更新仍须由 REST 补读，详见容器部署说明。Redis/持久事件流与多副本恢复属于后续验收项，不能因本地单进程握手通过而标记为全生产实时能力完成。

JDY-31蓝牙串口链路已退出项目。相关代码与旧记录只用于追溯早期联调，不再启动、不再扩展，也不作为当前、备份、演示或验收链路。

## ESP8266与IoTDA链路

ESP8266-01S不再使用ESP-AT方案，而是运行项目自定义Arduino UART-MQTT桥固件：

```text
STM32 USART2
  → ESP8266-01S UART JSON
  → 本地Mosquitto
  → IoTDA安全转发网关
      ├─→ 华为云IoTDA（云端路）
      └─→ Django POST /api/telemetry/（平台路，幂等入库 + 阈值告警）
```

ESP8266以9600 bit/s接收以 `\r\n` 结束的 `ut.telemetry.v1` JSON，发布到 `ut/v1/CTRL-01/telemetry`，并将 `ut/v1/CTRL-01/cmd/#` 下行消息转发回STM32。Wi-Fi与本地Broker配置仅保存在被忽略的 `firmware/esp8266-01s/include/secrets.h`。

IoTDA网关订阅本地遥测，使用Zod校验结构后双路输出：经MQTTS和HMAC-SHA256认证转发至IoTDA；同时把同一条报文映射为Django批量契约报文，用仅限遥测POST的机器API Key经 `POST /api/telemetry/` 幂等写入平台。设备密钥和接入API Key只允许保存在受控密钥管理或部署环境。项目负责人已确认历史Wi-Fi密码为经授权的隔离台架配置，不作为误提交处理。IoTDA设备密钥是独立的云端凭据；在其授权范围未确认前仍建议轮换，并只保存在受控本地环境。网关配置、字段映射与失败重试策略见 [IoTDA网关说明](../services/iotda-gateway/README.md)。

## Django 主栈批量报文

单次请求允许 1—100 条读数。每条读数必须具有稳定且全局唯一的 `eventId`，资产编码必须已存在并处于启用状态，时间使用带时区的 ISO 8601。

## STM32 串口报文

STM32 每 2 秒从 USART2 写入一行 JSON，行末必须是 `\r\n`；`assetCode` 必须已存在于平台资产台账。STM32 没有 RTC 时可省略 `ts`，API 会以接收时间记录。

```json
{
  "schema": "ut.telemetry.v1",
  "readings": [
    { "assetCode": "ENV-01", "metric": "temperature", "value": 29, "unit": "degC", "quality": "good" },
    { "assetCode": "ENV-01", "metric": "humidity", "value": 50, "unit": "%RH", "quality": "good" },
    { "assetCode": "SEEP-W01", "metric": "water.raw", "value": 2, "unit": "adc", "quality": "good" },
    { "assetCode": "LEVEL-L01", "metric": "level.detected", "value": 0, "unit": "bool", "quality": "good" },
    { "assetCode": "CTRL-01", "metric": "vibration.alarm", "value": 0, "unit": "bool", "quality": "good" }
  ]
}
```

下面是 Django 主栈批量接入报文示例：

```json
{
  "readings": [
    {
      "eventId": "sim:ENV-01:temperature:20260827T160000Z",
      "assetCode": "ENV-01",
      "metricKey": "temperature",
      "metric": "环境温度",
      "value": 30.2,
      "unit": "°C",
      "quality": "good",
      "recordedAt": "2026-08-27T16:00:00+08:00"
    }
  ]
}
```

字段要求：

- `eventId`：1—80 位安全字符；同一事件重试不会重复入库，使用相同编号提交不同数据会返回 `409`。
- `assetCode`：已启用资产的唯一编码。
- `metricKey`：稳定的机器指标键，用来匹配阈值规则；`metric` 是界面显示名称。
- `value`：有限数值，绝对值不超过 `1e9`。
- `unit`：指标已配置阈值时，必须与阈值单位完全一致。
- `quality`：`good`、`suspect`、`bad` 或 `missing`；只有 `good` 参与自动规则。
- `recordedAt`：不得早于当前时间 30 天，允许最多 5 分钟的采集端时钟漂移。

## 一致性与告警闭环

整个批次采用数据库事务：资产、单位、事件号或字段校验任一失败，整批回滚。系统不会出现“前几条成功、后几条失败”的部分提交。

当 `metricKey` 存在阈值配置时：

1. 达到预警值，创建一条带 `ruleKey` 的自动告警并将资产标记为关注。
2. 达到报警值，升级同一活动告警和资产状态，不重复创建告警。
3. 回落至预警值以下，自动解决该规则告警，并根据资产其他活动告警重算资产状态。
4. 自动创建、升级、恢复以及批次写入都写入审计日志。

数据库对同一资产、同一规则的活动告警设置部分唯一约束，应用事务和数据库约束共同防止并发重复。

## 软件验证

无需 MQTT 或硬件，可使用任何现有 HTTP 调用能力向 Django API 提交上述 JSON。管理员和运维员可以写入，查看者只能读取。验证重点包括：

- 同一报文连续提交两次，第二次 `duplicates` 增加且数据库记录数不变。
- 将温度从正常值提升到预警/报警值，只存在一条活动规则告警且级别正确升级。
- 将温度恢复到预警线以下，告警自动解决，资产状态恢复。
- 在批次末尾制造事件号冲突，确认批次前部的新事件没有落库。

接口完整错误码和响应结构见 [API 契约](api-contract.md)。MQTT/IoTDA 到 Django 的正式接入适配器须在后续硬件联调阶段按该契约实现，不得绕过 API 或直接访问数据库。

## 实体台架验证

在 API 使用的数据源中先运行迁移与种子，再执行 `python manage.py configure_ingest_principal` 并配置机器 API Key，然后：

```powershell
# 终端 1：Django 后端
cd backend
python manage.py runserver

# 终端 2：IoTDA 网关（双路输出，.env 中配置 DJANGO_API_URL 与 DJANGO_INGEST_API_KEY）
cd services/iotda-gateway
npm install
npm start
```

网关对每条 STM32 遥测输出 `Django stored N reading(s)` 后，前端顶部选择 API 数据源并成功登录，环境读数无需刷新页面即可更新；温度越限时告警页会出现自动规则告警。未知资产编码、非数值数据、错误口令或不符合结构的报文会被 API 拒绝并记录错误，不会写入数据库。
