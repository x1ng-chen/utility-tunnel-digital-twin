# 可信遥测接入说明

## 当前软件链路

当前主链路为 `软件数据源 → Django REST API → PostgreSQL → 阈值规则 → 告警/资产/审计 → Vue 3`。本阶段只实现和验证软件能力，不依赖开发板、MQTT Broker 或任何需要用户额外安装的软件。

遥测通过 `POST /api/telemetry/` 批量写入。前端在 API 模式下通过仪表盘“刷新数据”读取数据库最新状态，并明确显示最近同步时间；当前没有把轮询伪装成实时推送。

实体台架另有一条已实测兼容链路：`STM32 → JDY-31 → Windows 蓝牙串口 → 串口网关 → Fastify API → PostgreSQL → SSE → React 前端`。该链路用于当前硬件联调，不代表 JDY-31 能直接访问云平台，也不替代后续华为云部署和正式主栈接入。

## ESP8266与IoTDA链路

ESP8266-01S不再使用ESP-AT方案，而是运行项目自定义Arduino UART-MQTT桥固件：

```text
STM32 USART2
  → ESP8266-01S UART JSON
  → 本地Mosquitto
  → IoTDA安全转发网关
  → 华为云IoTDA
```

ESP8266以9600 bit/s接收以 `\r\n` 结束的 `ut.telemetry.v1` JSON，发布到 `ut/v1/CTRL-01/telemetry`，并将 `ut/v1/CTRL-01/cmd/#` 下行消息转发回STM32。Wi-Fi与本地Broker配置仅保存在被忽略的 `firmware/esp8266-01s/include/secrets.h`。

IoTDA网关订阅本地遥测，使用Zod校验结构后经MQTTS和HMAC-SHA256认证转发至IoTDA；设备密钥只允许保存在被忽略的本地环境文件或受控部署环境。项目负责人已确认历史Wi-Fi密码为经授权的隔离台架配置，不作为误提交处理。IoTDA设备密钥是独立的云端凭据；在其授权范围未确认前仍建议轮换，并只保存在受控本地环境。

当前证据边界：

- STM32行式JSON发送已通过JDY-31实体链路验证；
- ESP8266桥固件与IoTDA网关代码已提交；
- ESP-01S真机烧录、Broker消息、断网恢复、连续运行和真实IoTDA收发尚需形成正式验收记录；
- IoTDA遥测尚未统一写入Django/Vue主栈，不能把云端转发代码视为完整平台闭环。

## Django 主栈批量报文

单次请求允许 1—100 条读数。每条读数必须具有稳定且全局唯一的 `eventId`，资产编码必须已存在并处于启用状态，时间使用带时区的 ISO 8601。

## JDY-31 实体台架配置

JDY-31 是透明蓝牙串口。串口网关从 Windows 蓝牙 SPP 端口读取以换行结束的 JSON，携带设备令牌提交至 Fastify API。每个有效报文先写入 `telemetry_reading`，再通过认证后的 SSE 连接推送给 React 前端；前端每 10 秒的 API 回读仅用于断流后的状态校正。

## JDY-31 串口网关配置

在 `services/api/.env` 设置设备入口令牌：

```dotenv
DEVICE_INGEST_TOKEN=请填写不少于32位的随机字符串
```

在 `services/serial-gateway/.env` 设置同一个令牌，并使用已确认的蓝牙串口：

```dotenv
SERIAL_PORT=COM10
SERIAL_BAUD_RATE=9600
API_URL=http://127.0.0.1:8080/v1/device/telemetry
DEVICE_ID=CTRL-01
DEVICE_INGEST_TOKEN=请填写与API完全相同的随机字符串
```

不要把数据库地址、令牌或云端凭据提交到仓库。

## STM32 串口报文

STM32 每 2 秒从 USART2 写入一行 JSON，行末必须是 `\r\n`；`assetCode` 必须已存在于平台资产台账。STM32 没有 RTC 时可省略 `ts`，API 会以接收时间记录。

```json
{
  "schema": "ut.telemetry.v1",
  "readings": [
    { "assetCode": "ENV-01", "metric": "temperature", "value": 29, "unit": "degC", "quality": "good" },
    { "assetCode": "ENV-01", "metric": "humidity", "value": 50, "unit": "%RH", "quality": "good" },
    { "assetCode": "SEEP-W01", "metric": "water.raw", "value": 2, "unit": "adc", "quality": "good" },
    { "assetCode": "CTRL-01", "metric": "vibration.alarm", "value": 0, "unit": "bool", "quality": "good" }
  ]
}
```

下面是 Django 主栈批量接入报文示例：

```json
{
  "readings": [
    {
      "eventId": "sim:ENV-01:temperature:20260827T160000Z",
      "assetCode": "ENV-01",
      "metricKey": "temperature",
      "metric": "环境温度",
      "value": 30.2,
      "unit": "°C",
      "quality": "good",
      "recordedAt": "2026-08-27T16:00:00+08:00"
    }
  ]
}
```

字段要求：

- `eventId`：1—80 位安全字符；同一事件重试不会重复入库，使用相同编号提交不同数据会返回 `409`。
- `assetCode`：已启用资产的唯一编码。
- `metricKey`：稳定的机器指标键，用来匹配阈值规则；`metric` 是界面显示名称。
- `value`：有限数值，绝对值不超过 `1e9`。
- `unit`：指标已配置阈值时，必须与阈值单位完全一致。
- `quality`：`good`、`suspect`、`bad` 或 `missing`；只有 `good` 参与自动规则。
- `recordedAt`：不得早于当前时间 30 天，允许最多 5 分钟的采集端时钟漂移。

## 一致性与告警闭环

整个批次采用数据库事务：资产、单位、事件号或字段校验任一失败，整批回滚。系统不会出现“前几条成功、后几条失败”的部分提交。

当 `metricKey` 存在阈值配置时：

1. 达到预警值，创建一条带 `ruleKey` 的自动告警并将资产标记为关注。
2. 达到报警值，升级同一活动告警和资产状态，不重复创建告警。
3. 回落至预警值以下，自动解决该规则告警，并根据资产其他活动告警重算资产状态。
4. 自动创建、升级、恢复以及批次写入都写入审计日志。

数据库对同一资产、同一规则的活动告警设置部分唯一约束，应用事务和数据库约束共同防止并发重复。

## 软件验证

无需 MQTT 或硬件，可使用任何现有 HTTP 调用能力向 Django API 提交上述 JSON。管理员和运维员可以写入，查看者只能读取。验证重点包括：

- 同一报文连续提交两次，第二次 `duplicates` 增加且数据库记录数不变。
- 将温度从正常值提升到预警/报警值，只存在一条活动规则告警且级别正确升级。
- 将温度恢复到预警线以下，告警自动解决，资产状态恢复。
- 在批次末尾制造事件号冲突，确认批次前部的新事件没有落库。

接口完整错误码和响应结构见 [API 契约](api-contract.md)。旧版 `services/api` 的 MQTT/SSE 能力仅作为兼容基线保留，不属于当前 Vue 3 + Django 主入口。

## 实体台架验证

在 API 使用的数据源中先运行迁移与种子，然后登录前端并选择 `API` 数据源。启动 API 后，在另一个终端启动串口网关：

```powershell
cd services/serial-gateway
npm install
npm run start
```

网关显示 `Forwarded telemetry` 后，前端顶部选择 API 数据源并成功登录，环境读数无需刷新页面即可更新。未知资产编码、非数值数据、错误令牌或不符合结构的报文会被 API 拒绝并记录错误，不会写入数据库。
