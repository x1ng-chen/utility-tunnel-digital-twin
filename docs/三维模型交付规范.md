# 三维实体模型交付规范

本规范用于将 Blender 制作的综合管廊实体模型安全接入运维平台。模型交付前不要求连接任何硬件；平台会在加载后自动核验每台设备的节点绑定状态。

## 交付位置

- 默认模型文件：`frontend/public/models/utility-tunnel.glb`
- 如使用其他托管地址，可在部署环境中配置 `VITE_TWIN_MODEL_URL`。
- 请交付 `.glb` 二进制文件及一份节点清单，不提交 Blender 自动备份、贴图缓存或临时文件。

## 设备节点命名

每个可定位设备必须在模型中拥有一个独立节点。平台按以下优先级匹配：

1. 设备台账的实体模型字段，例如 `MESH_ENV_01`。
2. 设备编码，例如 `ENV-01`。
3. 平台兼容名称，例如 `ASSET_ENV_01`。

节点名称需唯一，连字符、下划线和大小写应与台账一致。模型可以包含管廊结构、灯光和装饰节点；只有匹配的设备节点才会接收告警高亮和点击定位。

## Blender 导出要求

- 导出格式使用 glTF Binary（`.glb`），应用对象的缩放与旋转变换。
- 保留设备节点名称，不要在导出前合并全部设备网格。
- 以米为单位建立场景，避免极端尺度；模型原点应靠近管廊主体。
- 材质使用标准 PBR 材质。告警状态由平台以发光效果叠加，不应烘焙为固定红色。

## 接入验收

进入“三维孪生中心”后，右侧“实体模型接入”会显示已定位设备数量：

- 显示“预览场景”表示尚未找到可加载的实体模型，系统仍可使用交互式示意场景。
- 显示“模型已加载”但数量未满，说明模型已加载但部分节点名称未匹配；按页面提示补齐节点即可。
- 数量与设备总数一致后，再分别验证正常、关注和告警状态的颜色与点击定位。
