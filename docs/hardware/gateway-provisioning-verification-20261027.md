# 网关UART配置栈溢出修复与联网验收

日期：2026-10-27（Asia/Tokyo）。范围：一块ESP32-S3 N16R8汇总网关；没有烧录STM32或小智语音终端，没有发布执行器控制命令。

## 缺陷与修复

`2026.10.27.1 / f5592dc5bad1ac41`的Flash写入、独立回读和启动身份检查通过，但后续实物配置查询复现了`A stack overflow in task loopTask has been detected`，部分配置回执在重启前截断。启动成功不能证明UART配置接口可用。

Arduino-ESP32在当前SDK配置下默认给主循环任务8 KiB栈。该任务还执行配置JSON解析、NVS记录校验和回执格式化。修订版使用SDK的`SET_LOOP_TASK_STACK_SIZE(24576U)`显式提供24 KiB任务栈，并在配置回执加入`loopStackMinFreeBytes`。该值在ESP-IDF Xtensa端按字节报告；主机桩返回0，不能当作硬件测量。

修复版本：`2026.10.27.2`，Build ID：`e805176c4320e92d`。没有通过缩短请求编号或绕过配置校验规避问题。

## 复现与记录

1. 使用修订版发布包进行散列验证；保留原始完整Flash，额外备份当前应用和NVS。
2. 确认Bootloader和分区兼容后，只更新网关应用；独立回读并核对启动身份。
3. 用发布包`provision_gateway.py --port <实际串口> --action status`发送标准32字符请求编号查询，核对对应回执、版本和栈测量。
4. 使用本机已有凭据或交互式私密输入配置。MQTT主机必须为电脑在同一热点内的当前地址，不能沿用另一网络下的旧IP。
5. 在保存配置前启动服务端订阅，确认配置保存、重启保留及网关新连接事件；不发送执行器命令。

本机保留故障串口原文、升级前后读回、状态查询回执、MQTT观察记录及服务端连接日志。凭据、芯片标识、实际网络地址、Flash/NVS二进制和私人路径不进入此公开说明。

## 尚未覆盖

没有验收四STM32采集、31路传感器、RS-485指令回执、实际风机动作、全负载稳定性或网关NTP校时。网关`online=true`只说明本次Wi-Fi到MQTT连接成立，不代表现场节点在线。电脑热点IP由DHCP分配，变化后应更新网关MQTT地址。
