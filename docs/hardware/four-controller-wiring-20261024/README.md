## 2. 物理走线

```text
                        后侧 / 图上方
              GW-01 ── CTRL-01 ─────── CTRL-02
                          P1              P2
                                          │
                             P5           │
                              ╲           │
                       CTRL-03 ─────── CTRL-04
                          P3              P4
                        前侧 / 图下方

485路径：GW-01 → CTRL-01 → CTRL-02 → CTRL-04 → CTRL-03，末端不闭合。
P5的传感器线束单独走到CTRL-03，不串入485，也不跨接多个MCU。
```

上/下是俯视方位，前/后只是本规划施工标记；实际展示正面可调整，不重编号。网关放左上近CTRL-01的干区，语音终端可放靠展示者的一侧，天线不贴金属管壁，麦克风避开风机直吹。

- 线槽分为通信/小信号和负载电源两类，风机、继电器、MQ加热和灯带的大电流回线避开ADC与麦克风；交叉处尽量短。
- 各检测站到所属主控是一束本地传感器线；P5到CTRL-03用一束独立线，逐根标P5-MQ2/P5-MQ4/P5-CO/P5-FLAME，不能靠颜色区分设备身份。
- 模拟信号与对应参考地成对敷设；氧气裸探头到所属板ADC的线尽量短，避开风机、MQ加热和灯带回流，不新增调理板。
- 液位探头位于接水盘低处，连接点、主控、分电端子放在干区；接头留检修余量，不以概念线长当裁线尺寸。

## 3. 四板共用的485接线

**仅针对选定的JSM485黑板，其商品图明确采用TXD接MCU TX、RXD接MCU RX的命名。其他模块不能照搬。**

| JSM485引脚 | 每块STM32连接 | 网关ESP32-S3连接 |
| --- | --- | --- |
| 3V3 | 本区3.3V | 网关板3.3V，核对供电余量 |
| GND | 本区GND | 网关GND |
| TXD | PA2 / USART2_TX | GPIO17，配置为UART TX |
| RXD | PA3 / USART2_RX | GPIO18，配置为UART RX |
| NC | 悬空 | 悬空 |
| A/B/GND端子 | A/B双绞主干＋低压参考地 | 相同定义 |

ESP32的GPIO17/18是N16R8开发板的候选资源，不是GPIO43/44下载串口；按实物确认确已引出。保持GPIO19/20 USB、启动脚与PSRAM/Flash引脚空闲，不把GPIO35～37当普通备用脚。网关板和语音板只通过网络共用平台，不额外互接UART；语音配件引脚沿所刷小智板型配置单独核对，本接线表不猜测该固件配置。

| 模块位置 | SW1 / 120Ω |
| --- | --- |
| GW-01，主干起点 | ON |
| CTRL-01、CTRL-02、CTRL-04 | OFF |
| CTRL-03，主干末端 | ON |

总线A/B不能星型分四路，也不能闭合成环。细参考地不承担风机/MQ/灯带负载回流。核对板载偏置和TTL输入空闲上拉，复位及未初始化期间保持不发送；从站只在合法请求后回复。自动收发模块仍需实测切换与恢复，不能依赖“零丢包”宣传。

建议初始19200 bit/s；8E1为待协议冻结的建议格式，不是现有固件配置。四个从站地址建议1～4；寄存器与命令字段由通信契约单独冻结。

## 5. 局部I²C总线

| 主控 | SCL / SDA | SHT地址（7位） | 同总线INA226 | 处理 |
| --- | --- | --- | --- | --- |
| CTRL-01 | PB6 / PB7 | SHT-01：0x44 | FAN1：0x40 | 保留原总线与已设地址 |
| CTRL-02 | PB10 / PB11 | SHT-02：0x45 | 无 | 原SHT-02迁移本板，保留地址 |
| CTRL-03 | PB10 / PB11 | SHT-03：0x44 | 无 | 原SHT-03迁移本板，保留地址 |
| CTRL-04 | PB10 / PB11 | SHT-04：0x45 | FAN2：0x40 | 原SHT-04/INA-FAN2迁移本板 |

初版沿用软件I²C，100kHz作为调试目标，避免新增DMA冲突。各板本地总线不互连；两块INA都用0x40没有跨板冲突。扫描核对实际地址与空闲电平，SCL/SDA上拉只到3.3V，并检查模块上拉并联后的负载。SHT的AL悬空；ADDR沿已验证焊桥保留，不能对已短接GND的焊桥再直接接3.3V。

### 风机电源测量与继电器实体

按[风机重新规划表](fan-wiring.md)施工：两风机分别在靠CTRL-01、CTRL-04的对角外侧排风，补风口与排风口错开；业务管道不承担风道功能。表内PB8/PA7/PA1在两块不同主控上各自独立。

```text
12V分区支路 → 保险/限流 → 继电器常开触点 → INA226模块电流采样通路 → FAN+
风机负极 → 本区负载回线 → 电源分配点
INA226逻辑侧VCC=3.3V；SCL/SDA接本区I²C
```

以上是功能连接顺序，不是对未知INA模块端子针序的猜测。实际IN+/IN-、VBUS、分流器与负载端按模块原理图核对；不把12V测量端接到INA的逻辑VCC。保留原R010模块和标定参数的来源，迁移后重新核对零点、方向及实际电流。

- 如果现有继电器是一块双路PCB，整体保留，共用逻辑参考地，IN1由CTRL-01控制，IN2由CTRL-04控制；两个触点回路分别标风机1/2。不要把“两路”误当必须新增两块板。
- PWM经过原开集电极/开漏驱动，保留限流与默认偏置；不把风机内部上拉电压直接送MCU。PWM目标沿原25kHz方案，实际兼容性和0%行为复测。
- TACH先确认输出类型，使用适配至3.3V的信号；软件采用原每转2脉冲的值前核对实际风机。
- **本次按新方案重接，不继承旧PC10基极线。** 断电后从旧控制板断开两路风机的全部旧PWM/TACH/继电器控制线并贴签，再分别按新板PB8/PA7/PA1接入。CTRL-01 PC10维持空闲；最终确认驱动输入只接所属板的PB8，不把旧PC10/PB9线并入。
- 上电/复位默认继电器不吸合、蜂鸣器关闭、灯带关闭，具体有效电平与外部偏置必须验证。释放四线风机PWM不必然停转，不能仅凭PWM值报告停机。

## 7. 电源分区与电平处理

```text

    ├─ 12V风机2支路
    ├─ CTRL-01：5V分区稳压 → 主控5V输入 / MQ加热与液位模块
    ├─ CTRL-02：5V分区稳压 → 主控5V输入 / MQ加热与液位模块
    │                         └─ 5V灯带独立受保护分支
    ├─ CTRL-03：5V分区稳压 → 主控5V输入 / MQ加热与液位模块
    ├─ CTRL-04：5V分区稳压 → 主控5V输入 / MQ加热与液位模块
    ├─ 5V网关稳压支路 → ESP32-S3开发板已确认的5V输入
    └─ 5V语音稳压支路 → 语音开发板 / 已适配功放
各区3.3V → SHT、485、INA逻辑侧和屏幕等，板载稳压余量逐区核对
```

复用现有供电能力；上图是分支与回流规划，不要求每个分支新增一个独立电源，也未冻结电源购买型号。12V不绕闭合环路，负载按分支接入；5V在就近位置稳压，避免长距离共用细5V线。所有低压参考地有确定回路，负载回流不串过ADC/MCU细地线。

- 主控开发板按已确认5V入口供电，不能往3V3脚灌5V；外接3.3V与板载3.3V不能直接并联。
- 屏幕、摇杆、SHT与INA逻辑侧按3.3V目标；ESP与功放等脉冲负载不从STM32板载3.3V供电。
- 接USB编程时选择单一供电路径，或核对板上电源隔离/反灌保护，不能假定两块开发板都有电源自动切换。
- 给每个负载分支设置与线束/接插件额定值匹配的保护；容量、线径与保护额定值按最终电流和压降确定，不凭本表给未知电源放行。
- 滤波和去耦按具体稳压器/模块资料保留；ADC参考与逻辑3.3V在风机启动、灯带全亮和语音播报时测量。

### 7.2 传感器接口的具体条件

| 设备 | 接线要求 |
| --- | --- |
| MQ-2 | 沿原方案使用DO；5V加热/模块电源独立供给，按用户确认的3.3V信号直接接GPIO，AO悬空 |
| MQ-4 / MQ-7模块 | 沿原AO采集；按用户确认的0～3.3V输出直接接ADC，不额外重复降压；不把供电5V等同信号5V |
| MQ-7加热 | 保留完整模块接法并核对实际传感器/加热电路；MQ-7系列有高低温检测周期要求，不能把恒定5V模块原始值当已标定CO浓度；本表不擅自增加或短接加热控制 |
| 火焰 | 供电沿实际模块额定值；按用户确认的3.3V DO接本表GPIO，供电电压与信号电压分列 |
| 液位FS-IR02 | 沿原DO干湿采集；5V模块供电，按用户确认的3.3V DO直接接GPIO |
| AO-02氧气 | 用户指定裸探头直连ADC、不新增调理板。按原厂图识别1号正极→所属ADC，负极参考→本区模拟地；2/3号为负极，不按VCC/GND/AO三针模块接线，不加外部电源 |
| SHT / INA | 逻辑侧3.3V，共地，I²C上拉3.3V；INA测量侧与逻辑供电区分 |

AO-02三路直连位置保持O2-01→CTRL-01 PC3、O2-02→CTRL-03 PA5、O2-03→CTRL-04 PA6。原厂空气中输出9～13mV；若ADC参考为3.3V，12位理想步进约0.806mV，空气读数仅约11～16个计数。这说明直连可作为原始信号试验，但不能据此声称精确氧浓度或可靠缺氧阈值；去噪平均不能消除全部量化、失调和负载误差。ADC使用模拟输入、无上下拉，长采样时间为实现目标，校准/源阻抗/通道切换稳定性需实测。保留原始ADC、电压与“未验证精度”质量标志；本轮不新增氧气自动保护阈值。原厂推荐放大电路作为性能对照保留，不列为本轮必须采购项。

## 8. 固件资源与默认态

| 主控 | 资源规划 |
| --- | --- |
| 全部STM32 | USART2 PA2/PA3用于485；USART1 PA9/PA10保留下载/调试；SWD PA13/PA14保留；不占用BOOT/USB/晶振/板载按键 |
| CTRL-01 | SPI3副屏（DMA2_CH2可复用）；TIM4_CH3/PB8风机1；PA7转速；软件I²C PB6/7 |
| CTRL-02 | SPI1主屏（DMA1_CH3）、SPI2灯带（DMA1_CH5）与ADC1并存；USART1保持轮询/中断，避免启用占用同DMA通道的RX；I²C保持软件实现 |
| CTRL-03 | 5个外部ADC通道＋5个数字输入＋本地I²C；中央P5保持独立设备身份 |
| CTRL-04 | TIM4_CH3/PB8风机2；PA7转速；软件I²C PB10/11 |

ADC1扫描/DMA可用DMA1_CH1作后续实现候选，当前没有修改驱动。CTRL-02摇杆另占2个ADC通道，连同外部2路模拟量共4路，不与主屏PA5/PA7冲突。

所有数字传感器默认周期扫描并保持短脉冲/报警事件；不要为每个DO盲目开启EXTI。CTRL-03的PB13与PC13共用EXTI13编号，不能同时映射为两个独立外部中断；本方案两者均按扫描输入，火焰如需中断另核对PB14与PC7。

CTRL-01的PB3在复位后属于JTAG，屏幕启用前必须关闭JTAG、保留SWD；PA15/PB4不接新增执行器。GPIO默认态、输出有效极性、看门狗与重启恢复须在新固件逐板验证。

## 9. 本地保护能力边界与报警定位

- CTRL-01、CTRL-04分别控制本区风机，CTRL-02控制唯一蜂鸣器/灯带，CTRL-03没有直接连接执行器。
- 因此CTRL-03的P3/P5报警要驱动其他板风机或集中声光，依赖总线网关协调。网关停机后仍可本地采集/锁存，但不能声称它能跨板排风/鸣响。这符合已确认“集中跨区联动暂不可用”的边界。
- 若后续要求网关故障时全区仍能驱动集中报警，需要另行增加硬接线报警或节点间自治机制；本轮不擅自接额外线路。
- 现场标签不变，保持physicalTag→controllerId→既有assetCode→GLB对象→P1～P5的显式关联。更改引脚不能把设备随数组顺序重编号。
- 逐站验证P1～P5各至少一路报警定位，并核对31路对象；CRC/遥测到达不等于三维绑定正确。

## 10. 迁移与验证顺序

1. 旧台架断电标线，记录板号、接头和原针脚；保留原接线表与镜像。拆开旧风机控制线，按新版统一针脚独立重接；核对四板型号。
2. 先空载检查电源分区、参考地、3.3V与5V没有误接，再连接网关和一块STM32的485模块。
3. 使用新通信固件验证一主一从请求/响应、CRC、复位和断线；不把旧USART2 JSON镜像直接并到总线。
4. 每区先接SHT与一条3.3V数字输入，再加0～3.3V模拟量；氧气按用户指定裸探头直连做原始值试验，核对正负极、不加电，不把低计数当已验收的氧浓度。
5. 按本表迁移两屏/摇杆/风机及执行器，旧输出线与新输出线不同时接同一个IN脚；逐项检查上电默认态和回执。
6. 扩展四节点及P5，最后接灯带与语音负载，测试风机启动、灯带全亮、语音播报并行时电压和通信。
7. 重新核对资产与模型绑定，做五站定位、离线/恢复及同站多报警测试；记录实际版本和未完成项。

静态检查可运行：

```powershell
python docs/hardware/four-controller-wiring-20261024/validate_wiring.py
```

输出[validation-report.json](validation-report.json)，检查31路、7/6/11/7、五站归属、引脚复用、ADC通道、同板I²C地址和调试接口占用。它不连接串口、不上电、不烧录，也不能代替万用表、示波器和实物测试。
