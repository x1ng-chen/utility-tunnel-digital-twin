## 2. 业务痛点、智能体边界与主闭环

原平台可以看数据和处理告警，但人需要在遥测、台账、工单、链路日志之间来回核对。新增智能体把“查到什么、为什么怀疑、还需确认什么、准备如何处理”串成一条可审查的路径。

核心闭环：

```text
STM32 采集 → ESP8266/MQTT/网关 → Django 数据库 → 遥测/告警/三维
                                                   ↓
用户问题 → Agent 选择白名单工具 → 参数与权限校验 → 查询结果/时间/质量
                   ↑                                  ↓
                   └──────── 工具结果回馈模型 ←─────────┘
                                ↓
                  证据引用 + 排查建议 + 待确认工单草案
                                ↓ 人工审阅与确认
                 既有工单 API → 分派/处理/复核 → 审计
```

这是单智能体、受控工具调用方案，不为参赛强行增加多智能体、框架、向量数据库或重新训练模型。LLM 用于问题理解、查询编排和建议组织；阈值告警、在线状态、权限、控制回执继续由确定性程序负责。

AI 不进入 STM32 的安全控制循环。模型断网/超时，不影响固件采集与原页面控制。硬件操作仍由用户走原控制页面和回执机制；Agent 没有自动下发动作工具，也不保证任何现场动作已经执行。

## 3. 现有基础与事实边界

硬件基线按已确认的双 STM32F103RCT6 节点、两套 ESP8266-01S、双 ST7735S 与 NodeB 摇杆菜单推进；31 个外部传感器：SHT30×4、液位×4、火焰×5、MQ-2×5、MQ-4×5、CO/MQ-7×5、氧气×3；INA226×2 单独统计。Agent 不要求新增 MCU 或重新烧录。

31 传感器演示链路与云/前端接入已有历史阶段证据，但不等于所有气体已标定、长期稳定性已通过或节点恢复问题已消除。实际比赛演示之前须重新核查运行中的固件、传感器台账、链路和采样时间。本地数据库也可能含演示/历史记录，AI 不能把它们当作现场实时读数。

保留原华为云方向：云端运行后端、数据库和前端，并提供外部 HTTPS 访问；GitHub 仅托管源码，不能代替服务器。板侧断网/云端中断要如实显示过期/离线，不用模拟数据冒充实时。现场演示模拟事件必须显著标“故障注入/模拟”，不能用于人员安全判断。

## 5. 推荐演示场景

### A. 链路异常巡检（优先完成）

从真实节点上报开始，询问某节点最新数据。断开该节点网路或用测试环境过期心跳模拟，Agent 查询时间和绑定状态，指出“链路异常，不等于气体浓度正常/传感器坏了”，检索离线手册，查询已有工单后生成草案。用户确认创建，平台显示工单编号和审计；恢复上报，看到新的采样与接入时间。是否关闭工单由人工复核决定。

### B. 告警解释与处置

测试环境注入明确标记的规则越限值，显示告警及三维定位；Agent 查告警、最新值和数据质量，解释是何项规则触发、哪些信息仍缺失；生成排查建议与草案。禁止使用明火或真实危险气体冒险演示，禁止把原始 ADC 说成可信浓度。

### C. 拒绝与降级

查看者尝试建工单、采集账号请求 Agent、要求执行 SQL/shell/直接开继电器、数据缺失或时间来自未来、DeepSeek 超时。展示拒绝/未知/过期，而非编造完成状态；原平台采集和确定性控制仍可使用。

建议视频流程 4–5 分钟：痛点→真实采集→询问→证据→人工确认工单→异常恢复→拒绝越权。该时长是团队建议，不是官方要求。

## 8. 风险、优先级与答辩重点

P0：核实官方材料规范和校赛安排；确认队长与学历资格；既有代码/多人贡献授权；真实 DeepSeek 工具循环联调；采样时钟和数据标记；部署 worker/proxy 超时与密钥；越权/提示注入测试；云端外网验证；禁止 AI 接管安全执行器。

P1：工单与告警源绑定及跨对话语义去重；证据友好字段与资产跳转三维；扩展实际排查手册并由负责人审核；结果句子与证据自动对照；题集与错误分析。

P2：按需建立向量检索、报告归档、成本缓存和请求取消；必须先证明当前知识规模与并发需要，不以框架数量充当创新。

答辩应能回答：为什么不是简单聊天页面（可观察的工具循环与工单闭环）；为何不用 LLM 直接控制（实时性、幻觉、安全职责）；与规则告警分工（规则触发、Agent核查解释）；数据过期怎么办（时间/质量/心跳）；气体是否标定（未标定不能安全判断）；如何评估效果（固定题集与人工参照）；模型和数据断网怎么办（确定性链路独立）；云端真正运行在哪里（服务器/容器，而非 GitHub）；何处创新（硬件事实、孪生资产、运维知识、证据和人工确认的结合，不宣称自研基础模型）；哪些是演示而非生产能力（如实列明）。
