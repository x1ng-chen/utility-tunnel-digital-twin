# 三维实体模型发布与交付规范

## 1. 交付文件

- 建模源文件使用 Blender `.blend`，由建模人员归档，保留材质、修改器和打印版本。
- Web 运行文件必须从 Blender 导出为二进制 glTF 2.0（`.glb`）。浏览器不直接加载 `.blend`，避免依赖 Blender、缩短下载时间并保证 Three.js 可解析。
- 单个 GLB 默认不超过 32 MB。系统会校验扩展名、GLB 2.0 文件头、声明长度、数据块边界和 SHA-256；校验失败的文件不会进入版本库。

## 2. Blender 导出约定

1. 应用需要交付的缩放与旋转，清理隐藏测试对象、未使用材质和重复网格。
2. 单位统一为米，坐标原点放在实体底座中心，Y 轴为高度方向的转换由导出器处理。
3. 选择 `File > Export > glTF 2.0`，格式选择 `glTF Binary (.glb)`；仅导出正式集合，并启用材质与网格压缩前的兼容性检查。
4. 每个需要告警定位的设备必须保留独立节点，节点名称与设备台账的“实体模型”字段完全一致。

推荐命名为 `MESH_<设备编码>`，将短横线改为下划线，例如：

| 设备编码 | Blender 节点名称 |
| --- | --- |
| `CTRL-01` | `MESH_CTRL_01` |
| `ENV-01` | `MESH_ENV_01` |
| `SEEP-W01` | `MESH_SEEP_W01` |

名称只使用大写字母、数字和下划线，且不得重复。告警、GIS、设备台账和三维视图都以设备编码关联，不依赖节点在文件中的排列顺序。

## 3. 发布与回滚

1. 管理员进入“系统配置 > 三维模型版本”，填写唯一版本号、说明并选择 GLB。
2. 上传成功只生成“待启用”版本，不影响当前运行场景。
3. 确认节点映射和页面预览后点击“启用此版本”。系统以数据库约束保证任意时刻只有一个使用中版本，并记录上传人、启用人、时间、校验码和审计日志。
4. 新版本异常时，在历史版本上点击“回滚到此版本”。历史文件不会被覆盖。
5. 三维页面使用登录凭证下载使用中模型，并在浏览器内生成临时地址；未登录用户不能通过模型直链下载。

## 4. 告警联动验收

- 点击设备可聚焦到对应节点，滚轮、双指或“＋/－”按钮可近距离查看，重置按钮恢复完整模型视角。
- 未关闭告警优先于设备台账状态：严重告警显示红色呼吸高亮，关注状态显示黄色，正常显示绿色。
- 三维、GIS、告警和工单之间可按同一设备编码互相跳转。
- 模型缺少节点时，页面必须明确列出未映射设备，并继续提供可点击的降级标记，不能虚报模型已经完整交付。

## 5. 部署与备份

- 容器使用持久卷 `twin_model_media` 保存模型；数据库只保存版本元数据和文件路径。
- 数据库备份与模型卷必须在同一备份批次生成，并记录 SHA-256。只恢复数据库或只恢复文件都会造成版本记录不一致。
- 正式环境通过 `TWIN_MODEL_MAX_BYTES` 调整文件上限；反向代理的请求体上限不得小于该值。
- 发布前至少验证：上传非法文件被拒绝、重复版本被拒绝、启用、回滚、未登录下载被拒绝、登录后模型加载、节点点击、告警高亮和近距离缩放。
