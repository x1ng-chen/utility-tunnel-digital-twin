# 双屏摇杆系统菜单设计

## 目标

为综合管廊双节点样机增加一套由模拟摇杆控制的嵌入式系统菜单。节点2作为唯一交互主屏，展示统一遥测、实时时间、报警和设备控制；节点1作为自动轮播的状态副屏。界面采用已确认的工业深色纵向菜单和“安全总览 + 分类详情”结构，目标菜单动画为 60 FPS。

本设计不替代 Web 前端或华为云 IoTDA。屏幕、本地前端和云端共享同一设备状态和命令回执，不各自维护未经确认的假状态。

## 用户体验

### 节点2主屏

主菜单包含：

1. 安全总览
2. 分类监测
3. 报警中心
4. 风机控制
5. 灯带与蜂鸣器
6. 通信状态
7. 系统设置

顶部状态栏常驻 `CTRL-02` 在线状态、MQTT 状态和 `HH:MM` 实时时间。主屏首先显示整体“安全/预警/报警”结论，并显示正常项、预警项和报警项数量。分类监测分为：

- 环境：温度、湿度；
- 气体：氧气、甲烷、一氧化碳、烟雾；
- 积水火情：液位、火焰；
- 风机供电：两台风机的目标占空比、实际转速、电压、电流和运行状态。

风机1和风机2均支持独立启停及 30%、60%、100% 预设转速，并提供“两台联动启动”和“全部停止”。灯带支持关闭、白色照明、绿色正常、黄色预警、红色报警、蓝色巡检、呼吸和闪烁模式，亮度提供 25%、50%、75%、100%。蜂鸣器支持测试、静音和恢复报警。

普通参数只有在按下摇杆后才下发。两台联动启动、全部停止和蜂鸣器静音必须显示二次确认框。命令状态依次显示为“待确认、发送中、已执行或失败”；只有收到节点1的匹配回执后才能显示“已执行”。

### 节点1副屏

节点1副屏不接摇杆，不提供设备控制。正常状态下每 5 秒自动轮播环境、气体和风机状态页。发生报警时立即停止轮播，显示红色报警详情；报警恢复后回到自动轮播。

### 摇杆操作

节点2使用五针模拟摇杆：

| 摇杆引脚 | 节点2 STM32 | 用途 |
|---|---|---|
| `GND` | `GND` | 公共地 |
| `+5V` 丝印脚 | `3.3V` | 避免 ADC 输入超过 3.3 V |
| `VRx` | `PC0 / ADC1_IN10` | 水平方向 |
| `VRy` | `PC1 / ADC1_IN11` | 垂直方向 |
| `SW` | `PC4` | 内部上拉，按下为低电平 |

上/下移动选中项，左返回上一级，右进入当前项，短按确认，长按 1 秒返回主菜单。持续保持上/下时先等待约 350 ms，再连续滚动。启动时在摇杆保持释放的条件下采样中心值；运行时应用中心死区、迟滞和按键消抖，防止松手后菜单漂移。

## 屏幕与引脚

两块屏幕均为 ST7735 128×128 RGB565，仅写 SPI，不使用 MISO。

### 节点2主屏

节点2沿用开发板预留屏幕接口的电源和四根控制线，只把时钟与数据改接 SPI1：

| 屏幕 | 节点2 STM32 |
|---|---|
| `GND` | `GND` |
| `VCC` | `3.3V` |
| `SCL` | `PA5 / SPI1_SCK` |
| `SDA` | `PA7 / SPI1_MOSI` |
| `RES` | `PB6` |
| `DC` | `PB7` |
| `CS` | `PB8` |
| `BLK` | `PB9` |

`PA6` 不连接。该映射不影响节点2的 `USART1 PA9/PA10` 调试串口和 `USART2 PA2/PA3` ESP 串口。

### 节点1副屏

节点1的 `PB6/PB7` 已用于 SHT30，`PA7` 已用于风机2转速反馈，因此不能复制节点2的 SPI1 接线。副屏使用 SPI3：

| 屏幕 | 节点1 STM32 |
|---|---|
| `GND` | `GND` |
| `VCC` | `3.3V` |
| `SCL` | `PB3 / SPI3_SCK` |
| `SDA` | `PB5 / SPI3_MOSI` |
| `RES` | `PC4` |
| `DC` | `PC5` |
| `CS` | `PB8` |
| `BLK` | `PB9` |

节点1固件关闭 JTAG 并保留 SWD，以释放 `PB3`；烧录和调试仍使用 `PA13/PA14`。该映射不改变 SHT30、气体传感器、液位、烟雾、火焰、两台风机、INA226、继电器、WS2812、蜂鸣器或 ESP 的现有接线。

## 渲染与性能

- 两块 STM32 使用外部晶振和 PLL，以 72 MHz 运行；APB1 保持不超过 36 MHz，ADC 时钟保持不超过器件限制。
- 节点2的 SPI1 和节点1的 SPI3 均以 18 MHz、SPI Mode 0、MSB first 发送。
- 屏幕使用 SPI DMA 和小型行缓冲，不分配约 32 KB 的完整帧缓冲。
- 菜单逻辑与屏幕驱动分离。菜单状态机只生成页面状态和动画进度，渲染器根据脏矩形更新 ST7735 GRAM。
- 动画时钟为 60 Hz：选中条约 140 ms 平滑移动，页面约 180 ms 横向滑入，确认框使用短淡入；动画期间 UART 接收、摇杆扫描和安全任务不得阻塞。
- 实时时间每秒更新；普通遥测到达后立即局部更新；风机转速、电压、电流目标更新周期为 500 ms。
- 节点1提升主频后，必须重新计算风机 PWM、WS2812 SPI 编码、软件 I2C 延时、ADC 分频和 UART 参数，保持现有外设实际频率不变。

全屏 RGB565 数据量为 32768 字节；18 MHz SPI 的理论传输时间约 14.6 ms。完整页面实际目标为 45–60 FPS，菜单行等小区域动画保持 60 FPS。若实机长杜邦线在 18 MHz 下出现花屏，允许按 12 MHz、9 MHz 的顺序降速，但仍通过局部刷新保持 60 FPS 菜单动画节拍。

## 数据与命令链路

### 状态数据

节点1继续产生可信的 `ut.telemetry.v1` 遥测。ESP-01 发布到本地 MQTT，网关继续写入 Django/PostgreSQL 并上报 IoTDA，同时向节点2生成一个适合串口传输的统一状态快照。节点2不得只解析现有温湿度子集；快照需要包含：

- 所有传感器值、质量和采样时间；
- 报警等级与报警来源；
- 两台风机的目标占空比、实际转速、电压、电流和运行状态；
- 继电器、灯带、蜂鸣器状态；
- 节点1、网关、IoTDA 的在线状态；
- 最近一次命令的标识和执行结果。

超过 5 秒没有更新的数据变灰并标记“数据陈旧”。MQTT 离线时主屏锁定所有控制入口，但仍显示最后一份数据和离线状态。节点1的本地安全联动不依赖 MQTT，断网时继续运行。

### 实时时间

ESP-02 联网后使用 NTP 校时，通过 USART2 将纪元时间和校时状态发送给节点2 STM32。STM32 使用系统节拍在两次同步之间续走时间。断网后继续显示最后校准的时间；断电重启且尚未校时时显示 `--:--`。节点1副屏从 ESP-01 的网络时间或状态快照取得同一时间基准。

### 控制闭环

节点2 STM32生成带唯一 `cmdId`、目标设备、动作、参数和有效期的菜单命令，经 USART2 交给 ESP-02。ESP-02 将其发布到面向 `CTRL-01` 的本地 MQTT 命令主题。ESP-01 已订阅 `ut/v1/CTRL-01/cmd/#`，把命令转发给节点1 STM32。

节点1先校验命令格式、范围、有效期和当前安全状态，再执行动作，并使用现有 `ut.command.ack.v1` 格式返回包含相同 `cmdId` 的回执。回执经 ESP-01、MQTT 和 ESP-02 返回主屏。5 秒内没有匹配回执即显示超时；迟到回执可以更新设备实际状态，但不能把已经超时的旧确认框改成成功。

菜单命令与 Web 前端命令共用节点1的执行和回执逻辑。安全联动优先级始终高于手动命令：甲烷、烟雾、火焰等已启用的可靠报警可以强制通风、红色闪烁和蜂鸣；未完成硬件标定的氧气和一氧化碳通道只显示数据，不擅自驱动执行器。

## 软件边界

实现应拆分为以下可独立测试的模块：

- `ui_state`：页面、选择、确认框、命令状态和动画进度；
- `joystick`：ADC 采样、自动校准、死区、迟滞、消抖和重复事件；
- `ui_renderer`：主题、文字、图标、脏矩形和 ST7735 绘制；
- `st7735_bus`：节点2 SPI1 DMA 与节点1 SPI3 DMA 的板级适配；
- `screen_snapshot`：完整遥测快照解析、陈旧判断和显示模型；
- `menu_command`：命令生成、串口发送、回执匹配和超时；
- `network_time`：NTP 同步报文与 STM32 本地续时。

这些模块通过结构体和事件接口协作，不让页面绘制函数直接操作 MQTT、UART、GPIO 或执行器。

## 错误与安全处理

- ADC 校准样本异常时显示“摇杆校准失败”，不产生方向事件；
- SPI DMA 超时后停止本帧、复位屏幕总线并在下一周期重绘，不阻塞安全任务；
- 无效或过期命令由节点1拒绝并返回原因；
- 控制期间网络断开，立即结束“发送中”并显示网络不可用；
- 主屏重启后从实际状态快照恢复，不沿用上次未确认的候选值；
- 报警页面可以覆盖普通菜单动画，且不得被用户手动配色或静音永久压制；
- 蜂鸣器静音应有期限或在新报警出现时自动失效，具体采用“新报警重新鸣响”。

## 验证与验收

### 自动化验证

- 原生单元测试覆盖菜单导航、边界循环、长按返回、确认框和 5 秒超时；
- 摇杆测试覆盖中心偏移、死区、迟滞、消抖、保持连滚和 ADC 极值；
- 快照解析测试覆盖完整、缺失、越界、乱序和陈旧数据；
- 命令测试覆盖 `cmdId` 唯一性、允许动作、参数范围、回执匹配、迟到回执和安全拒绝；
- NTP 时间测试覆盖首次同步、断网续时和未校时显示；
- Node A、Node B、两套 ESP、网关和相关后端测试均通过；
- 构建产物检查 RAM/Flash 占用，不依赖完整帧缓冲。

### 实机验收

- 节点2摇杆各方向、短按、长按和保持操作均稳定，无松手漂移；
- 主屏菜单行动画稳定 60 FPS，整页切换无明显撕裂或闪屏；
- 两块屏幕连续运行 30 分钟无花屏、死机或 UART 丢帧；
- 主屏显示的传感器和执行器状态与前端、串口日志一致；
- 两台风机的独立/联动命令、预设转速和实际回执逐项验证；
- 灯带模式、亮度、蜂鸣器测试/静音逐项验证；
- 断开 MQTT 后控制入口锁定，恢复后自动重新同步；
- 触发已验证的甲烷、烟雾或火焰报警时，两块屏幕切换报警状态，本地安全联动覆盖手动设置；
- 若 18 MHz SPI 不稳定，记录最终稳定分频和接线长度，不以花屏状态通过验收。

## 实施顺序

1. 抽离可在主机测试的菜单状态机、摇杆事件和命令状态模块；
2. 升级节点2时钟、SPI1 DMA 和摇杆输入，完成主屏本地假数据导航；
3. 扩展 ESP-02 的 NTP、状态快照和菜单命令发布；
4. 扩展节点1遥测、命令执行与回执，并完成节点2真实数据闭环；
5. 升级节点1时钟，在保持现有外设频率的前提下接入 SPI3 DMA 副屏；
6. 完成安全联动、异常处理和双屏实机验收。

## 非目标

- 不在 STM32 上保存华为云密钥或直接连接 IoTDA；
- 不让节点1副屏承担本地控制；
- 不为 128×128 屏实现触摸操作；
- 不在未标定的氧气或一氧化碳数据上新增自动执行策略；
- 不重做 Web 前端或三维模型。
