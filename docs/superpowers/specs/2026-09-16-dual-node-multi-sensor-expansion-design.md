# 双节点多传感器扩展设计

## 目标与范围

在保留现有双屏、ESP、风机、继电器、蜂鸣器、灯带和调试接口的前提下，将以下传感器接入 Node A 与 Node B，并让每个传感器拥有独立编号、遥测和报警定位能力：

- SHT30 × 4
- 火焰传感器 × 5
- MQ-4 × 5
- MQ-2 × 5
- 氧气传感器 × 3
- 一氧化碳传感器 × 5
- 液位传感器 × 5

本设计不接入四路继电器，不改变当前风机继电器方案，也不处理待更换的 WS2812 灯带硬件。

## 总体架构

Node A 与 Node B 分别采集本地传感器。Node A 经 ESP-01 发布 `CTRL-01` 遥测；Node B 经 ESP-02 发布新增的 `CTRL-02` 本地传感器遥测，同时继续承担菜单控制和远端快照显示。每条读数必须包含唯一 `assetCode`，平台和屏幕不得只汇总成无法定位来源的单一报警。

Node A 负责全部四个 SHT30、7路模拟传感器和9路数字传感器。Node B 负责6路模拟传感器和6路数字传感器。两节点不跨板共享模拟线或数字检测线。

## 引脚冲突审计

以下现有功能必须保留，新增分配没有复用其中任何引脚。

### Node A现有保留引脚

- ESP-01 USART2：PA2、PA3
- USB-ISP/调试 USART1：PA9、PA10
- SWD：PA13、PA14
- 板载状态LED：PA8
- 风机继电器：PA1
- 风机转速：PA6、PA7
- 风机PWM：PB8、PB9
- 蜂鸣器：PB0
- Screen 1 SPI3：PB3、PB5
- Screen 1控制：PC4、PC5、PC6、PC7
- WS2812：PB15
- 两条软件I²C：PB6、PB7、PB10、PB11

Node A新增模拟脚PA0、PA4、PA5、PB1均具备ADC1输入功能，且未被以上外设占用。新增数字脚PC8～PC13未被当前固件使用。PC13只作为液位模块的高阻数字输入；不得用它直接驱动LED、继电器或其他负载。

### Node B现有保留引脚

- ESP-02 USART2：PA2、PA3
- USB-ISP/调试 USART1：PA9、PA10
- SWD：PA13、PA14
- 板载状态LED：PA8
- Screen 2 SPI1：PA5、PA7
- Screen 2控制：PB6、PB7、PB8、PB9
- 摇杆ADC：PC0、PC1
- 摇杆按键：PC4

Node B新增模拟脚PA0、PA1、PA4、PA6、PB0、PB1均具备ADC1输入功能。PA6虽然是SPI1_MISO复用脚，但现有屏幕为单向发送，只使用PA5 SCK和PA7 MOSI，因此PA6可安全配置为模拟输入。新增数字脚PC6～PC11未被当前固件使用。

### 审计结论与实施前提

- 13个模拟传感器对应13个独立ADC引脚，没有通道复用冲突。
- 15个数字传感器对应15个独立GPIO，没有与屏幕、串口、摇杆、风机或调试接口冲突。
- 四个SHT30使用两条总线和两种地址，没有I²C地址冲突，前提是每条总线上的两个模块确实可分别配置为0x44和0x45。
- PB2/BOOT1、BOOT0、PA13/SWDIO和PA14/SWCLK均未分配给传感器，保留下载与调试能力。
- PD0/PD1保留给外部高速晶振，PC14/PC15保留给低速晶振/备用，均不参与本方案。
- 最终接线前必须确认所用开发板排针实际引出了PC8～PC13；MCU封装具备这些引脚，但不同核心板可能没有全部引出。

## 电气设计约束

MQ系列加热器使用独立5V电源。电源容量按模块实测启动电流并保留至少30%余量选型；不得由STM32的3.3V轨或开发板小电流稳压器供电。Node A、Node B、两块ESP、传感器电源和风机控制地必须共地。

任何STM32输入不得超过3.3V：

- 模拟输出按模块最大输出电压设计分压，不能只按当前万用表读数判断。
- 5V模块的数字输出必须经确认是开漏/3.3V兼容；否则增加电阻分压或电平转换。
- 每路模拟输入在分压后使用1kΩ串联电阻，并在ADC引脚侧使用100nF对地电容作为首版低通滤波；只有在记录波形和响应时间后才能变更该组合。
- 长线传感器使用星形供电、就近去耦，并将模拟线与风机PWM、继电器和MQ加热电源线分开布线。

## 固件职责

### Node A

扩展现有轮询表和遥测轮转，不再使用“每类只有一个全局值”的结构。每个物理输入拥有独立状态：原始值、滤波值、在线状态、质量、采样时间和报警状态。

四个SHT30按两条总线依次采集；模拟通道使用统一ADC采样接口；数字输入使用独立去抖状态。安全联动必须明确来源：任一已启用MQ-4、MQ-2或火焰通道进入报警都可触发对应安全策略，但离线或未校准通道不得误触发。

### Node B

新增本地传感器采集模块，同时保留现有摇杆、屏幕、ESP串口和菜单命令路径。采样任务必须有时间预算，不能阻塞UI、时间同步、命令回执或ESP串口。

ESP-02增加Node B本地遥测发布路径。菜单命令仍发布到 `ut/v1/CTRL-01/cmd/menu`，Node B传感器遥测使用 `ut/v1/CTRL-02/telemetry`，两类流量不得混用。

## 标识与遥测

建议使用以下稳定编号：

- `SHT-01`～`SHT-04`
- `FLAME-01`～`FLAME-05`
- `MQ4-01`～`MQ4-05`
- `MQ2-01`～`MQ2-05`
- `O2-01`～`O2-03`
- `CO-01`～`CO-05`
- `LEVEL-01`～`LEVEL-05`

每帧继续使用 `ut.telemetry.v1`，但每条reading按物理传感器填写独立 `assetCode`。质量至少区分 `good`、`suspect`、`bad`、`missing`。未完成校准的模拟气体传感器只能上报原始ADC/电压和 `suspect`，不得伪造浓度单位。

## 屏幕行为

Node A屏幕显示本节点传感器摘要，Node B屏幕提供Node A与Node B分类浏览。首页只显示每类最严重状态和异常数量；进入监测页后可逐个查看编号、数值和质量。报警覆盖层必须显示具体来源编号，例如 `FLAME-04`，不能只显示 `FLAME`。

屏幕更新采用最新完整快照；慢传感器采样不得阻塞时间显示、菜单输入和命令回执。传感器离线显示 `OFF` 或 `--`，不得保留旧值并伪装为实时数据。

## 错误处理与安全

- 单个传感器故障不能阻塞同总线或同节点的其他传感器。
- I²C错误需执行有界恢复并记录具体总线、地址和故障类型。
- ADC越界、饱和或断线应进入非good质量，不参与未经定义的自动联动。
- 数字报警必须去抖，并定义各模块实际高/低有效极性。
- 启动阶段在GPIO配置完成前不得因浮空输入触发继电器、风机或蜂鸣器。
- 新增传感器必须逐个启用；未接通道在配置中禁用，避免批量误报警。

## 实施顺序

1. 记录每种现有模块的供电、AO/DO范围和有效电平。
2. 仅接入并验证四个SHT30。
3. 逐路接入模拟传感器，先验证电压范围，再连接STM32。
4. 逐路接入火焰、MQ-2数字输出和液位输入，确认极性与去抖。
5. 完成Node A多实例采集和遥测。
6. 完成Node B本地采集、ESP-02上报和双节点显示。
7. 最后启用多源报警联动。

## 验收标准

- 32个传感器都能以唯一编号上报，且来源节点正确。
- 任意一路断开后，只影响该路并在限定时间内显示离线。
- 所有ADC引脚在最坏输入情况下保持0～3.3V。
- 四个SHT30可连续运行，不出现地址冲突或总线锁死。
- Node B在本地传感器满负载采样时，菜单控制仍能在既有超时窗口内收到回执。
- 时间显示、风机控制、双屏刷新和MQTT重连不得因新增采集退化。
- 报警界面能显示具体传感器编号，未校准通道不输出虚假浓度。
