# Agent可靠性、专业知识与效果证据补齐

本轮先完成不依赖付费调用的软件工作。真实模型复测按用户决定暂缓，人工试验和独立评分没有运行。本目录补充原软件冲刺交付，不修改历史实测记录，也不代替实物验收。

| 项目 | 本轮交付 | 仍需验证 |
|---|---|---|
| Agent可靠性 | 历史失败分类、最终回复离线校验、引用与工具结果检查、任务完成检查、失败保留部分结果 | 更新代码后真实模型能否改善工具选择、任务完成、耗时与用量 |
| 专业知识 | 原6条GB 51354摘要，新增9条GB/T 50838选定正文摘要；本地混合检索、版本/条款约束和无答案拒答 | 完整标准覆盖、后续变更与工程适用性；模型引用的语义正确性 |
| 效果证据 | 12复合场景＋30题的事实核对与评分标准、人工任务模板、组名遮蔽评分包、严格评分导入 | 实际人工任务、独立人工评分及冻结新版本的单/三Agent复测 |

## 可靠性修复

- 不存在设备返回有来源的“未命中”，不能作为已登记或已有测量的证据。
- 被拒的调用只能列入`rejection_ids`说明失败，不能混入测量`evidence_ids`；中文紧邻编号也检查。
- 结构化数值须出现在所引工具返回中，不能仅因为全局快照里有这个数就引用无关手册；这仍不等于核验全部自然语言。
- 拒绝重复JSON字段、多个JSON块、非有限数字、伪造文本工具调用和错误数组类型。一次格式纠正继续计入总预算，不增加无限重试。
- 补充取证阶段必须实际成功查询；旧证据不能伪装新查询。局部快照只登记实际出现的设备。
- 空检索和历史双节点案例不能满足手册门槛。风机草案还要求用户明确参数和当前风机手册；外部标准不能直接批准动作。
- 五站巡检、排障、工单草案和恢复复核检查实际工具产物。未生成草案不能用一句“已准备”冒充完成。
- 预算、格式或供应商失败保留已有证据，清空可确认动作/草案并标记未完成。自然语言没有因此获得完整事实认证。
- 趋势窗口暴露2000条共享账本的截断情况，不能拿部分记录声称完整历史覆盖。
- 工单80条、活动告警100条的截断也明示；工单截断时保守拒绝新草案，不能用未命中证明不存在重复。全局未完成工单超过80条后的按设备分页能力仍未增加。
- 任务冻结完整知识清单；知识变更后使用旧清单时，不能套用新向量索引，明确降级关键词检索。

`failure-audit.json`对188条历史记录分类，其中51条明确遇到402，14条其他失败或旧记录无明确HTTP归因；不把所有失败都归为余额。回复离线校验只检查格式、字段及引用关系，不能模拟供应商下一次会如何推理。

## 知识来源与边界

[住建部修订公告](https://www.mohurd.gov.cn/gongkai/zc/wjk/art/2024/art_3383d6cebf26480cb76d49204a5fad44.html)确认更名和编号GB/T 50838-2015，修订自2025-04-01实施。选定正文来自中国建筑科学研究院建筑防火研究所的[通风系统](https://gf.cabr-fire.com/article-27563.htm)和[监控与报警系统](https://gf.cabr-fire.com/article-27566.htm)页面，并与其[局部修订说明](https://gf.cabr-fire.com/article-70229.htm)核对。没有宣称取得完整修订PDF或核实了全部后续变更。

新增条款：7.2.1、7.2.2、7.2.5、7.5.3、7.5.4、7.5.7、7.5.8、7.5.9、7.5.10。保存版本、条号、正文页面URL、抓取HTML散列、核验方式、摘要性质和适用限制。网页没有伪造PDF页码。仅收录自写短摘要，不分发标准全文。

特别注意：7.5.7的确认火灾联动与7.5.8的天然气超限联动方向不同。“一报警就开风机”不能作为统一策略。标准中的工程要求不能证明沙盘普通风机防爆、ADC已标定或系统已满足工程合规。

`knowledge-gold.json`包含20个检索目标/无答案用例。实际检索结果另见`knowledge-hybrid.json`与`knowledge-keyword.json`。通过率仅为该固定集合的top5目标与拒答检查，不是模型回答准确率。余下历史排除、注入权限、结构化引用与格式边界由自动测试检查。

## 评测的公平性修正

历史普通模型数据包只含初始5段知识，而Agent可以继续查全库；旧结果不足以证明RAG收益。新v2包冻结完整知识库、事实快照、代码指纹、实际模型与预算。普通问答使用相同的完整知识来源；单/三Agent使用相同总预算。

普通问答仍只有1次模型调用、没有工具，不能将其缺少闭环操作能力包装为诊断智力提升。主对照应为同快照、同知识、同模型、同代码和同总预算的单/三Agent。历史预算未记录时自动标记不可直接量化配对；不倒填历史元数据。

`scoring-status.json`的空评分保持待评，未填项不按0分，NA不进入对应维度分母。助手复核、自评和独立人工评分分别汇总。`completed`、复核pass、程序确认和事实正确不能互相替代。评分步骤、命令及人工任务时间记录见[评分操作说明](review-protocol.md)。

[评审包](review-bundles.zip)包含12个复合场景与30题的历史数据、66份历史回答及空表，协调者须按操作说明分别分发材料。散列见`review-bundle-manifest.json`，本轮检查与待验项目见[验证记录](validation.md)。

## 复现（均不调用付费模型）

在仓库根目录，使用已安装项目依赖的Python：

```powershell
.agent-demo/venv/Scripts/python.exe deploy/agent-demo/audit_agent_evidence.py
.agent-demo/venv/Scripts/python.exe deploy/agent-demo/check_knowledge_gold.py
.agent-demo/venv/Scripts/python.exe deploy/agent-demo/check_knowledge_gold.py --keyword-only
.agent-demo/venv/Scripts/python.exe deploy/agent-demo/review_agent_evidence.py build --output .agent-demo/review-new
```

新模型评测须另行显式启动`--live`；本轮没有启动。`curate_standard_sources.py`仅维护者显式联网刷新来源散列，运行后的标题/条号匹配不代替重新阅读正文。
