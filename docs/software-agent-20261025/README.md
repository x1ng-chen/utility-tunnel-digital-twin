温湿度一个模块需要温度、湿度两项指标都具备，才计为所需观测可用；仅有采集周期、心跳或单位不符的量不会计入。原始气体ADC不是校准ppm，氧气裸探头原始值不证明环境安全。模型身份与实物身份仍需核对，即便数据库观测可用也不等于接线验收通过。

## 2. 启用和复现

重启现有Django与Vue开发服务，或重新构建网页制品。无需数据库迁移即可加载新软件，但不会自动补齐台账。完整接入说明见[AI助手接入](../AI助手接入.md)。

只读巡检命令，在`backend`目录执行：

```powershell
python manage.py inspect_stations
python manage.py inspect_stations --station P5 --output 新巡检报告.json
```

`--strict`在缺项、观测不可用或激活模型节点未验证时返回失败。已有报告文件不覆盖。命令不会创建资产、改mesh、改硬件绑定或写入遥测。

自然语言流程需要服务端模型密钥。示例任务：

1. “巡检P1到P5，列出31路缺项、过期和不良数据。”
2. “排查P5告警，比较其他检测点、双风机转速与电流，引用手册来源并列出候选原因。”
3. “核查已有工单后，为MQ4-05准备处置草案，确认后再提交。随后只读复核指定工单的数据更新情况。”

每次最多6次白名单工具调用和7次模型调用，仍有55秒预算。完整长流程可分成多个问题；真实模型时延和工具选择准确率还未验收。

新网关上行配置（详见[网关说明](../../services/iotda-gateway/README.md)）：

```dotenv
LOCAL_DEVICE_IDS=CTRL-01,CTRL-02,CTRL-03,CTRL-04
```

ESP32-S3需分别发布`ut/v1/CTRL-01/telemetry`至`ut/v1/CTRL-04/telemetry`，每帧仍最多32项指标。全系统31个物理传感器的指标数超过31项，不能直接打包为单个旧版受限帧。该上行约定的软件能力已测试，S3实物与总线固件尚未联调。
