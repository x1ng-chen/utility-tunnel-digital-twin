# 华为云部署方案

> 状态：架构已选定，资源尚未创建。本文不包含账号、设备密钥、数据库连接串或公网地址。

## 1. 目标与边界

华为云是本项目的正式云端目标。云端用于承载软件平台、业务数据和设备接入；现场 STM32 的安全联动必须保持本地可用，网络中断不得把安全控制转移到云端。

```text
浏览器 ── HTTPS ──> ECS / Nginx ──> Django API ── 私网/TLS ──> RDS for PostgreSQL
                                  │
STM32 + ESP8266 ── MQTTS ────────> IoTDA ── 规则/应用订阅 ──────> API
```

| 层级 | 华为云服务 | 本项目职责 | 当前状态 |
|---|---|---|---|
| 网络与计算 | VPC、ECS、EIP、安全组 | 当前主入口承载 Vue 3 静态文件和 Django API | 未创建 |
| 数据库 | RDS for PostgreSQL | 资产、遥测、告警、工单、阈值与审计数据 | 未创建 |
| 设备接入 | IoT Device Access（IoTDA） | STM32/ESP8266 设备身份、MQTT(S) 上报与命令下发 | 香港实例、产品和CTRL-01设备已创建；真实遥测上行已验证 |
| 存储与备份 | OBS、RDS 自动备份 | 备份包、部署证据、演示材料和恢复演练产物 | 未创建 |
| 权限与运维 | IAM、Cloud Eye、LTS | 最小权限、监控告警、应用和运维日志 | 未创建 |

## 2. 部署原则

- **现场优先**：IoTDA 或公网不可用时，STM32 继续执行本地互锁、急停和已配置的保护策略。
- **网络隔离**：ECS 与 RDS 必须位于同一 VPC；RDS 不分配公网访问，API 仅通过私网 TLS 连接数据库。
- **最小暴露**：公网仅开放 `443/TCP`；`80/TCP` 仅用于跳转或证书校验；`22/TCP` 只对运维固定公网 IP 开放。不得开放 PostgreSQL `5432`、MQTT 或开发端口。
- **最小权限**：云资源由 IAM 子账号/用户组按职责授权；应用运行账号 `ut_runtime` 仅具备已审查的数据库列级权限。
- **密钥不入库**：JWT、数据库密码、IoTDA 设备密钥、证书和 IAM 访问密钥仅保存于华为云密钥管理或受控部署环境。
- **样品架构精简**：当前不部署Kafka、AMQP、FunctionGraph或DIS。统一遥测网关从本地Mosquitto取数，一路写入Django/PostgreSQL供Vue展示，另一路上报IoTDA；未来部署ECS后可按需改为IoTDA HTTPS回推。

华为云安全组用于约束 ECS 的入站和出站流量；ECS 创建时必须关联安全组。[华为云 ECS 安全组说明](https://support.huaweicloud.com/intl/en-us/usermanual-ecs/en-us_topic_0140323157.html)

## 3. 实施顺序

1. **网络与账号**：确定区域、创建 VPC/子网、安全组和最小权限 IAM 用户组；记录资源标签、负责人和成本归属。
2. **数据库**：创建 RDS for PostgreSQL，启用 TLS、自动备份和恢复保留策略；按 [部署与恢复手册](deployment-runbook.md) 运行迁移、种子和最小权限 SQL。
3. **应用**：创建 Linux ECS，在 Nginx 后部署 Vue Web 与 Django API；配置 HTTPS、`CORS_ALLOWED_ORIGINS`、`DATABASE_URL` 和健康检查 `GET /api/health/`、`GET /api/ready/`。
4. **设备云接入**：`utility-tunnel-controller` 产品与 `CTRL-01` 测试设备已经创建，真实台架遥测已完成MQTTS上行；下一步验证命令回执、断网恢复和持续运行。
5. **联调与验收**：验证浏览器登录、告警—工单闭环、RDS 备份恢复、IoTDA 断连重连和云端不可用时的本地保护。

IoTDA 支持 MQTT(S) 等设备接入方式；设备连接信息应从实例的“Access Details”获取，并使用该实例对应的证书与域名。[华为云 IoTDA 设备接入说明](https://support.huaweicloud.com/intl/en-us/devg-iothub/iot_02_0170.html)

## 4. IoTDA 对接约束

- 将现有 MQTT 主题和 JSON 报文映射为 IoTDA 的产品模型或受控自定义主题；映射结果写入接口 V0.2 后再固化到固件。
- 使用 MQTTS 和平台 CA 证书校验；设备凭据只写入烧录环境或安全配置分区，禁止提交到仓库。
- 首期只注册一台测试控制器 `CTRL-01`；批量注册、设备自注册和 OTA 不属于当前 M0/M1 验收范围。
- API 通过受控应用侧订阅或规则转发消费设备数据，统一落入现有 PostgreSQL 业务模型；不能绕过 API 直接由前端访问 IoTDA。
