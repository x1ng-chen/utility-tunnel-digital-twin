# 三维实体模型接入规范

## 模型交付

- 使用 Blender 导出 **GLB 2.0**：`frontend/public/models/utility-tunnel.glb`。
- 不提交 `.blend` 源文件到网页目录；源文件由建模组单独归档。
- 建议应用 Draco 压缩、嵌入贴图，单个网页模型控制在 30 MB 以内。
- 坐标采用米制，Y 轴向上；管廊主体中心建议在世界原点附近。

### `.blend`、3D 打印与网页三维的关系

- `.blend` 是 Blender 的**建模源文件**，用于队友继续编辑实体模型；浏览器不能直接、安全地加载它。
- 3D 打印可从同一 `.blend` 导出 STL/3MF；网页端则从同一源模型导出 GLB。两种导出互不替代，但应共享同一设备对象名称。
- 建模交付应包含：`.blend` 源文件、`utility-tunnel.glb`、贴图、对象命名表和导出版本说明。网页仓库只接收优化后的 GLB 与命名表。

## 设备命名与绑定

每个需要联动的设备必须是独立 Object / Mesh，名称优先使用资产主数据中的 `mesh` 字段。当前支持按以下顺序自动识别：

1. `mesh`，例如 `MESH_ENV_01`
2. 资产编码，例如 `ENV-01`
3. 规范别名，例如 `ASSET_ENV_01`

设备必须至少包含：`CTRL-01`、`ENV-01`、`SEEP-W01`、`VIB-01`、`FAN-01`、`LED-01`、`DISP-01`、`BUZZ-01`、`RELAY-01`、`MOIST-01`、`BT-01`、`PCB-01`。

## 状态联动

- 存在未关闭告警：红色高亮与呼吸光效。
- 资产处于关注状态：橙色高亮。
- 正常资产：青绿色高亮。
- 未核验或离线资产：灰蓝色高亮。

实际链路为：开发板遥测/人工确认 → 后端更新资产或生成告警 → 前端读取资产编码 → 按同编码定位 GLB 网格并变色。只要实体传感器的资产编码与 GLB 对象名称映射一致，出现未关闭告警时对应模型部件会自动标红；告警关闭后恢复为资产当前状态色。

模型缺失或单个设备未命名时，前端会显示可交互预览节点，不会中断系统运行。

## 配置

默认模型地址为 `/models/utility-tunnel.glb`。部署环境需要使用其他地址时，设置前端环境变量：

```text
VITE_TWIN_MODEL_URL=/models/utility-tunnel.glb
```
